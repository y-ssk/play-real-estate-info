# Claude Code 立ち上げキット（kickoff）

> 5枚のドキュメント（`01`/`02`/`DESIGN`/`04`/`99`）を起点に、構想フェーズの壁打ちと同じ進め方を Claude Code 上で再現するための手順とプロンプト集。
> 「いきなり実装」ではなく「読ませて理解を検品 → 器を決める → 役割を立てる → 記録の形式を決める → 最初の構造化タスク」の順で入る。

---

## 使う順番（全体像）

| 手順 | やること | 場所 |
|---|---|---|
| 準備 | リポジトリ作成・文書配置・melta-ui取り込み・APIキー | 手作業（Claude Code起動前） |
| Step A | 読ませて理解を検品する | Claude Code |
| Step B | ドキュメントの器（CLAUDE.md構成・配置）を決める壁打ち | Claude Code |
| Step C | 2役体制（実装役＋レビュー/検証役）を立てる | Claude Code |
| Step D | 記録の形式（ADR・学習メモ・コミット規律）を決める | Claude Code |
| Step E | 最初の構造化タスク（ETL基盤の一片）を依頼 | Claude Code |

Step B〜D は `99_decision-register.md` の保留筆頭そのもの。ここを Claude Code との壁打ちで順に確定していく。

---

## 準備（Claude Code 起動前・手作業）

1. **リポジトリを作る**：WSLネイティブFS（例 `~/dev/machilens`）に `git init`。`/mnt/c` 越しは避ける。
2. **5枚を置く**：`docs/` に `01` `02` `04` `99`、ルートに `DESIGN.md`（配置の最終形は Step B で確定するので暫定でよい）。
3. **melta-ui を取り込む**：`git clone` して必要な仕様書（foundations/components の md、tokens.json、prohibited.md）をコピー。MIT著作権表示を保持。
4. **MLIT APIキー**を申請・取得し、`.env` 等に置く（コミットしない）。
5. Claude Code 自体の作法（`CLAUDE.md` の読み込み・サブエージェント・設定）は公式ドキュメントで確認：`https://docs.claude.com/en/docs/claude-code/overview`
→Stepのどこかでスキル・サブエージェントを追加する

## 進め方の原則（最初に Claude Code へ渡す＝後で CLAUDE.md の核になる）

> 下記をそのまま最初のメッセージにするか、`CLAUDE.md` の冒頭に置く。

```
あなたはこのプロジェクトの開発パートナーです。以下の進め方を守ってください。

# 進め方（壁打ちモード）
- いきなり実装しない。まず関連ドキュメントを読み、理解を要約して私に確認する。
- 大きな判断（アーキ・設計・スコープ・ライブラリ選定・ディレクトリ構成）は、
  選択肢を「理由＋トレードオフ＋捨てる案」付きで提示し、私の決定を待つ。
- 1ブロックずつ進める。一度に全部を決め切ろうとしない。
- オーバーエンジニアリングを避ける。「本丸は手厚く、周辺は薄く」。
  本丸＝ETL・データモデリング・地図表現。周辺＝認証・UI部品・インフラ。
- 新しい検討事項が出たら、その場で解決せず docs/99_decision-register.md に
  「項目＋トリガー（着手条件・状態ベース）」で追記し、今の作業は止めない。
- 確定した判断は docs/99_decision-register.md に結論を追記する。
- 過去の経緯は判断材料であって制約ではない（「前にこうしたから」で積み上げない）。

# 変更管理（必須・docs/04_harness.md 第8節）
- コード変更時は、関連する仕様文書・ADR・必要なら学習メモを同じ変更で更新する
  （コードだけ・文書だけの更新は禁止。根拠と実態を常に一致させる）。
- 変更ごとに意味のある最小単位でコミットし、コミットメッセージに「なぜ」を書き、
  関連ADR番号を紐づける。Git履歴が意思決定の記録になるようにする。
- 「なぜそうしたか」は本丸を厚く、周辺は薄く残す。
```

## Step A：読ませて理解を検品する

```
docs/ 配下（01_project-overview-scope / 02_architecture / 04_harness /
99_decision-register）と DESIGN.md を全部読んでください。

そのうえで：
1. このプロダクトが何で、誰のためで、MVPで何を作るかを3〜5行で要約して。
2. アーキの骨格と、まだ未確定（保留）の項目を区別して挙げて。
3. 文書間の矛盾・抜け・不明点があれば指摘して。

実装やファイル作成はまだしないでください。理解の確認だけです。
```
→ 出力を読み、認識のズレがあれば文書を直す（文書化が正しいかの最終検証も兼ねる）。

---

## Step B：ドキュメントの器を決める（壁打ち）

```
docs/99_decision-register.md の保留筆頭「ドキュメントの器（CLAUDE.md形式＋配置）」を
一緒に決めたい。

方針：CLAUDE.md は薄く保ち、「各文書への地図＋最重要の行動指針」だけにする。
全部入りにしない（docs/04 第1節の入れ子構造の考え方）。

- 5枚（01/02/DESIGN/04/99）と CLAUDE.md・README.md を、ルート/docs にどう配置するか
- CLAUDE.md に何を書き、何を docs/ に委譲するか
を、選択肢を理由付きで提案して。決まったら 99 に結論を追記して。
```

---

## Step C：2役体制を立てる

```
開発体制を「実装役 ＋ レビュー/検証役」の2役で発進したい
（将来 BE/ETL役・FE役に分割する構想。docs/04 第3節）。

Claude Code でこれをどう構成するのが良いか提案して。
サブエージェント等の最新の作法は公式ドキュメントを確認したうえで示して。
各役に渡すコンテキストは役割別に絞る方針：
- FE役 … DESIGN.md 中心
- BE/ETL役 … 02_architecture とデータ仕様中心
レビュー役は docs/04 第5節の Feedback（特に層1：データの正しさ）を検証する。
```

---

## Step D：記録の形式を決める（最初の本丸の直前）

```
最初の本丸（ETL基盤）に着手する前に、記録の形式を決めたい（docs/04 第8節）。

互いに連動する形で、3つのテンプレートを提案して：
1. ADR（結論＋なぜ＋検討した代替案＋捨てた理由）。docs/adr/ に1決定1ファイル。
2. 学習メモ（理解を深めるための短い記録）。
3. コミットメッセージ（「なぜ」＋ADR番号の紐づけ形式）。

決めたら 99 の該当保留を確定に移し、テンプレートをリポジトリに置いて。
```

## Step E：最初の構造化タスクを依頼

自由文で投げず、必ず下記の型に落とす（docs/04：自由文でなく構造化タスク）。

### 再利用テンプレート
```
# タスク：<一言>
## 目的・背景
<なぜやるか／参照する文書：例 docs/02 の「○○」節>
## 対象
<触るディレクトリ／ファイル>
## 受け入れ条件
- <条件1>
- <条件2>
## テスト要件
<何をテストで担保するか>
## 記録
<残すADR／同時更新する文書>
## コミット
<粒度・メッセージ方針（なぜ＋ADR番号）>
```

### 最初のタスク（例：XIT002 取得クライアント）
```
# タスク：MLIT XIT002（都道府県内市区町村一覧）取得クライアントの実装
## 目的・背景
ETL基盤の最初の一片。全エンドポイント取得の入口（docs/02 マスタ）。
実装前に XIT002 の公式IF定義（リクエスト/レスポンスのスキーマ）を必ず確認する（憶測で書かない）。
## 対象
internal/mlit/（APIクライアント）、cmd/ingest/
## 受け入れ条件
- 首都圏9都県の市区町村一覧が取得できる
- レート制御（リクエスト間隔を空ける）が効く
- 取得結果を検証するテストがある
## テスト要件
Go の test。9都県それぞれで市区町村が取得でき、件数が妥当な範囲に収まる。
## 記録
「クライアント設計の理由／レート制御の方式／検討した代替」を docs/adr に残す。
## コミット
クライアント＋テスト＋ADR を1コミット。メッセージに理由とADR番号。
```

## 注意（正直なところ）

- **Step B〜D は未確定（保留）事項**。このキットは「決めるための入口」であって、答えそのものではない。Claude Code との壁打ちで確定させる。
- **Claude Code の機能（CLAUDE.md の自動読み込み・サブエージェント・設定）は変わり得る。** 必ず公式ドキュメントで確認：`https://docs.claude.com/en/docs/claude-code/overview`
- **5枚はまだ「中身」**。準備（リポジトリ配置・melta-ui取り込み）を済ませてからこのキットを使う。
- このキットは「壁打ちモード」前提。Claude Code が選択肢を返して判断を求めてくるのは想定どおり。即実装を期待しない。
