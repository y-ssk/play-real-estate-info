# CSS変数の3層トークンと cascade — なぜダークが「後付け1箇所」で効くか (2026-06-27)

## 学んだこと
- **トークン＝色や寸法に名前を付け1箇所で定義し、各所は名前で呼ぶ**仕組み。生値（`#d6443a` のような実値）を各部品に直書きしない。
- **3層に分ける**のが定石：
  - **生値層**（パレット）：`--slate-900: #0f172a` / `--coral-600: #d6443a`
  - **意味層**（役割で命名）：`--color-text: var(--slate-900)` / `--color-accent: var(--coral-600)`
  - **用途層**（部品が呼ぶ）：`.btn { background: var(--color-accent) }`。部品は色名を知らず「差し色をくれ」としか言わない。
- **cascade（CSS）**＝上位要素に置いた変数は配下の全子孫に自動で受け継がれる性質（DBの cascade とは別物）。`:root` に置けばページ全体で `var(--…)` が使える。
- だから**ダークは `body.dark { --color-text: …; --color-accent: … }` の1ブロック**で意味層の中身を差し替えるだけ。cascade が全子孫へ届け、**部品のコードは一切変えない**（`DESIGN`§5「後付けできる構造を保つ」を構造的に満たす）。

## なぜ重要 / どこで効く
- 同じ理屈を **TSオブジェクト（JS定数）** でやると詰まる：cascade が無いので「今ダークか」に応じて違う定数を全部品へ配り直す配線（React context 等）を自前で書く必要がある。「トークンならダークできる」のは正しいが、**楽に後付けできるのは“配り方”に cascade がある CSS 変数だから**。ここが選定の決め手だった。
- **論点を正しく絞る教訓**：「TS案はUI用とmap用に二分する」は誤った弱点提示だった。MapLibre は CSS変数も JS の style も読めず paint 式でしか色を受け取れない＝**地図が別経路なのはどの案でも同じ**（`mapTokens.ts`）。土台選定で本当に違うのは「普通のHTML要素の色の持ち方」だけ。選択肢を出すときは差が出ない軸を弱点に見せない。
- **新規ビルド依存ゼロ**：CSS変数も TS も素のまま動く。Tailwind はビルド工程（PostCSS等）が増える＝`ADR-0013`/`ADR-0021` の「依存・攻撃面を最小に」と逆行。
