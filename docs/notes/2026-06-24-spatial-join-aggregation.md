# 空間結合による集計の考え方（メッシュの按分を中心に） (2026-06-24)

## 学んだこと

### 集計の3パターン（単位ポリゴンへ空間結合）
集めたデータを「市区町村（＝単位ポリゴン）」に貼り付けて数える形は、データのgeometryの型で3つに分かれる。すべて `ADR-0006` の「単位ポリゴンへ空間結合／単位を差し替えれば同じ計算」に乗せる。

- **ポリゴン→面積率**：ハザード区域・用途地域など。`Σ ST_Area(ST_Intersection(unit, layer)) / ST_Area(unit)`。**交差面積で按分するのが正しい**（面積そのものを測る指標だから）。
- **点→件数/密度**：駅・地価地点・施設など。`COUNT(*) WHERE ST_Within(point, unit)`。点は1つの単位にしか入らないので**内包判定**でよい。密度は件数÷面積。
- **メッシュ→集約**：将来人口250mメッシュ（`XKT013`）など。メッシュの値（人口）を単位へ寄せる。**ここだけ「境界またぎ」の按分に選択肢がある**。

→ **パターンごとに按分ルールが違うのが正しい**（面積=交差按分／点=内包／メッシュ=後述）。

### メッシュが市区町村境界をまたぐ問題
人口データは250m四方のマス（メッシュ）に「このマスは何人」と入っている。市区町村の境界線はマス目と揃わないので、境界線の上に乗るマスが必ず出る。そのマスの人口をどちらの市に入れるか、が論点。

```
   横浜市 │ 川崎市
  ┌───┬─┼─┬───┐
  │   │ ▓ │   │   ▓ = 境界をまたぐ250mメッシュ（人口100人と仮定）
  └───┴─┼─┴───┘   この100人を横浜と川崎にどう振り分ける？
```

3つのやり方：
- **重心法**：マスの**真ん中の点（重心）がどちらの市に入るか**だけ見て、人口をまるごとそちらへ。重心が川崎側なら100人すべて川崎。
- **面積按分**：マスが横浜4割・川崎6割にかかるなら、人口も40人・60人に割って配る。
- **完全内包のみ**：境界にまたがるマスは捨て、中に完全に収まるマスだけ数える。

## なぜ重要 / どこで効く

### 重心法を採る理由（`ADR-0015` の決定）
1. **二重計上が起きない・合計が合う**：各マスは必ず1つの市にだけ入るので、足すと元の総人口に一致する。事実ベース（`ADR-0005`）を壊さない。
2. **「偽の精度」を避ける**：面積按分は「人口がマス内で面積に比例して均等に住む」という現実に無い仮定を置く。片側が山林・片側が住宅地は普通で、4:6で割る方がむしろ嘘になりうる。重心法は余計な仮定を足さない。
3. **実装が単純**：マスを「重心の点」として扱えば、点の内包判定（`ST_Within`）と同じ仕組みで済む。

採らない理由：
- **面積按分**＝精度が見かけ倒れになりやすく計算も重い、割に合わない。
- **完全内包のみ**＝外周のマスを丸ごと捨て、人口が過小に出る。事実をゆがめるので不可。

### メッシュ移行（v1）したときの影響 ← 朗報
集計単位を市区町村から250mメッシュそのものに降ろすと、**集計の単位と人口データのマス目が同じ250mグリッドに揃う**。すると：
- 人口は「マス＝単位」で1対1になり、**またぎ問題が消滅**する（按分の出番なし＝どの方法でも結果が同じ）。
- つまり**重心法を選んでもメッシュ移行で不利にならない**。むしろ移行で単純になる側。
- またぎが復活するのは、単位メッシュと元データのマス目のサイズ/基準がズレる場合（別系統の1kmメッシュ混在等）だけ。国土数値情報はJIS標準メッシュで揃うので `XKT013` どうしなら問題なし。

なお按分ルールはメッシュ集約だけの話で、ポリゴン（交差面積按分）・点（内包）は変わらない。
