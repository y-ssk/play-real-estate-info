# HTTPルーティングとは何か／なぜ標準 net/http で足りる (2026-06-25)

> 壁打ちで「ルーティングが何をしているか分からない」から噛み砕いた解説の保存（理解の蓄積）。採用判断＝`ADR-0020`、お作法＝`backend-conventions` §4。

## 学んだこと
- サーバ（Goのプログラム）は1プロセスで**全要求を1つの入口で受ける**。要求には「**メソッド**（`GET`/`POST` 等＝リクエスト方式）」と「**パス**（`/api/karte` という住所部分）」が乗る。
- **ルータ**＝来た「メソッド＋パス」を見て、**どの処理関数（ハンドラ）に渡すか振り分ける係**。建物の受付の交換台に相当。無ければURLを長い `if/else` で自前に読み分ける羽目になる。
- **用語の精度**：
  - **パス**＝住所部分（`/api/karte`）。**クエリ文字列**（`?unit=13101`）はパスとは別物で、ハンドラが解釈する。ルート照合には通常使わない。
  - **エンドポイント**＝API操作の呼び出し口で、「メソッド＋パス」を一体で指す一段上の語。**ルータが照合する生の項目を厳密に言うなら「メソッド＋パス」**（エンドポイントはメソッドを内包しがち）。
- **パス引数**：`/tiles/{z}/{x}/{y}` のように毎回変わる部分。ルータが (1) `/tiles/12/3637/1612` を型に当てはまると認識し、(2) 値 `12,3637,1612` を取り出してハンドラに渡す。昔これが標準に無く、皆 `chi`/`gorilla` を入れた主因。

## なぜ重要 / どこで効く
- **Go 1.22（2024）以降、標準 `ServeMux` がメソッド＋パスワイルドカードを公式サポート** → 「パス引数のためにライブラリ」が不要に。これが選定をひっくり返した核。
- 選定の軸＝**攻撃面最小**（依存を足すほど自分が書いていないコードがサーバ内で動く＝脆弱性・更新追従・供給網の心配）。標準だけなら依存ゼロ・一体型/単一バイナリと相性。
- **3段階の理解**：標準 `net/http`（道具は言語付属だけ）／`chi`（薄い便利部品を1つ足す・標準互換）／`gin`・`echo`（独自作法の大枠で全部面倒見る＝コードが染まる）。欲しいのはルーティングだけなので最小の標準が最適。足りなくなったら `chi` を後付け（可逆）。
