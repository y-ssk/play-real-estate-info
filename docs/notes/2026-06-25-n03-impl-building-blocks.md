## 学んだこと

### 1. `go.mod` / `go.sum` とは（Goの依存管理）
- **`go.mod`** ＝ このプログラム（モジュール）の宣言書。3つを持つ：①モジュール名（`github.com/y-ssk/machilens`）②`go` 行＝使う言語バージョンの下限（今回 `1.22` 維持）③`require`＝依存するライブラリと固定バージョン（今回 `github.com/jackc/pgx/v5 v5.7.2` を追加。pgx は Go から PostgreSQL に繋ぐライブラリ）。`// indirect` は「自分が直接呼ばないが依存先が必要とする孫依存」。
- **`go.sum`** ＝ 依存ごとの**ハッシュ値（中身の指紋）の台帳**。次に依存を取得するとき、記録した指紋と照合し、配布物のすり替え・改ざんが無いかを検証する（誰が・いつ取得しても同じ中身を保証＝再現性と、依存の出所のすり替え対策）。**手で編集しない**＝`go` コマンドが管理する。
- **なぜ Go 1.22 維持か**：`pgx` を最新に上げると Go のバージョン引き上げ（1.22→新版）を要求された。段0で定めた前提（Go 1.22・`go.mod` の `go` 行で固定）を崩さないため、Go は据え置き・pgx を 1.22 互換版（v5.7.2）に固定した。最新 pgx が要るなら Go 版上げの是非を別途判断する（可逆）。

### 2. シェルスクリプトの作法（`fetch-n03.sh` / `ingest-n03.sh`）
- **`set -euo pipefail`** ＝ 失敗に気づくための安全装置。`e`＝コマンドが失敗したら即停止／`u`＝未定義の変数を使ったらエラー／`pipefail`＝パイプ（`A | B`）の途中が失敗しても拾う。握りつぶさない。
- **秘匿の読み込み（self-source）** `[ -f ~/.config/config.env ] && source ~/.config/config.env` ＝ DB接続情報はリポジトリ外のファイルに置き、スクリプトが**実行時に読み込む**。中身は画面に出さない。これでどのシェルから呼んでも接続情報が揃う（対話・非対話・将来のCI）。
- **`: "${POSTGRES_USER:?メッセージ}"`** ＝ 未設定なら**値を出さずに**即エラー（`compose` の `${VAR:?}` と同じ思想）。
- **`trap 'rm -rf "$TMP_DIR"' EXIT`**（取得側）＝ 一時ディレクトリを終了時に必ず掃除する（成功・失敗どちらでも）。
- **入力を1件に確定**：`*.geojson` を glob で探し、0件/複数なら取り違えを避けて落とす（配布物のファイル名がダウンロード名と違うので決め打ちしない）。
- **冪等**：`unzip -o`（上書き）・`ogr2ogr -overwrite`（生テーブルを作り直す）＝何度流しても同じ結果。

### 3. 使い捨てコンテナで外部ツールを呼ぶ（`ogr2ogr`）
投入は GDAL 公式イメージの `ogr2ogr` を、その都度起動して捨てる形で呼ぶ（`ADR-0023`）。引数の意味：
- **`docker run --rm`** ＝ 1回だけ起動し、終わったら破棄。道具をホストにもDBイメージにも常駐させない。
- **`--network=host`** ＝ コンテナからホストの `localhost:5432`（compose が公開しているDB）へ届く＝`make migrate` と同じ流儀。
- **`-v "${DATA_DIR}:/data:ro"`** ＝ ホストのN03データをコンテナへ**読取専用で見せる**（コンテナにデータを焼き込まない）。
- **`-e PGPASSWORD="$POSTGRES_PASSWORD"`** ＝ パスワードを環境変数でコンテナに渡し、接続文字列（`PG:host=...`）には**埋めない**。プロセス一覧（`ps`）やコマンド履歴に出さないため（秘匿の死守）。

### 4. `ogr2ogr` の癖：列名の小文字化（実行で判明）
`ogr2ogr` は PostgreSQL に書き込むとき、**既定で列名を小文字化する**（LAUNDER＝識別子の正規化）。GeoJSON の属性 `N03_007` は、テーブルでは `n03_007` になる。これを知らず正規化SQLが `"N03_007"`（大文字・引用符付き）で参照していたため `column "N03_007" does not exist` で失敗した。小文字へ直して解消。
- **学び**：外部ツールが作るテーブルの列名は、**実物を見てから**参照する（憶測しない）。机上の前提（GeoJSONの属性名のまま）に頼らない。

### 5. なぜ投入（シェル/`ogr2ogr`）と正規化（Go）を分けるか
- **投入＝機械的**（図形をそのままテーブルに写す＝ツールが解決済み）／**正規化＝本丸**（5桁コードで束ねる・値域チェック・冪等＝層1の検証対象）。この継ぎ目（`ADR-0022`/`0024`）により、投入ツールを替えても正規化は不変。
- **接続情報の流れ**：正規化（Go）も同じ self-source スクリプトの中で実行するので、読み込み済みの接続情報をそのまま引き継ぐ（どのシェルから呼んでも同じに動く）。
