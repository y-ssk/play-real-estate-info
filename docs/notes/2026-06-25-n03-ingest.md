# N03境界の投入とは何か（投入工程・シェープ・座標系・ツール） (2026-06-25)

> 壁打ちで「投入が具体的に何をするか／シェープ・SRID・GDAL とは」を下の層から分解した保存。採用判断＝`ADR-0022`、お作法＝`backend-conventions` §5。

## 1. 「投入」とは具体的に何をする作業か
N03 の生データ（シェープファイル）を **PostGIS のテーブル**に変えること。工程：
1. シェープを読む（図形＋属性）
2. 文字コードを **CP932 → UTF-8** に直す（でないと市区町村名が文字化け）
3. PostGIS にテーブルを作る（**geometry 列を正しい SRID＝6668 で**）
4. 各ポリゴンを1行ずつ挿入
5. **空間索引（GiST）**を張る（空間検索を速く）
6. （別工程＝正規化）`N03_007` を5桁コードに整える・年度固定・値域チェック

**①〜⑤＝投入（機械的）／⑥＝正規化（本丸の結合基盤）**。誰がどこをやるかが案の違い。

## 2. シェープファイルとは
- 1990年代に Esri が作ったベクタ地理データ形式。古くからの定番。
- **「ファイル」だが複数ファイルの束**（同じ基本名でセット）：
  - `.shp`＝図形そのもの（座標列・本体）／`.shx`＝.shpへの位置索引／`.dbf`＝属性表（dBASE形式・1図形1行・**文字はここ**・都道府県名/市区町村名/コード）／`.prj`＝座標系定義／`.cpg`等＝補助。
- **文字コード・SRID指定が手作業になる根本理由**（シェープの古い設計の癖）：
  - 属性 `.dbf`（dBASE）は**文字コードの目印を持たない**伝統 → 日本の行政データは CP932 保存 → 投入時に `-W CP932` と**人が教える**。
  - 図形 `.shp` は**座標数値だけで SRID を埋め込まない**・座標系は `.prj` に**分離** → 投入時に `-s 6668` と**SRIDを指定**。
- **「シェープである限り」**：`shp2pgsql` はこの束しか読めない。新しい形式（GeoJSON＝1ファイルに図形も属性も座標系も入る、GeoPackage 等）もあり、配布形式は年度で変わりうる。シェープのうちは `shp2pgsql` で足り、別形式化したら多形式の `ogr2ogr` が要る。

## 3. 座標系・SRID・投影・再投影
- **座標系**＝点を数値の組で表す約束。**投影**＝丸い地球を平面に写す数学変換。**SRID**＝座標系の識別番号。
  - 6668＝JGD2011（日本最新・**保存はこれに統一**＝`ADR-0014`）／4612＝JGD2000（一つ前）／3857＝Webメルカトル（配信時）。
- **再投影（reprojection）**＝ある座標系の数値を別系へ変換し直す（例 4612→6668）。測地系をまたぐ専用数学＝**PROJ** ライブラリが担う。
- N03 が 6668 でなければ保存前に 6668 へ再投影（`shp2pgsql -s 4612:6668` ／ `ogr2ogr -t_srs EPSG:6668`）。最初から 6668 なら不要＝`.prj` で確認。

## 4. PostGISコンテナ・「同梱」・GDAL
- **PostgreSQL**＝土台のDB。**PostGIS**＝それに地理機能を足す**拡張**。**イメージ**＝ソフト一式の詰め合わせ、**コンテナ**＝起動した実体（`ADR-0013`＝`postgis/postgis` を使う）。
- **同梱**＝PostGIS を入れると付属の小道具も一緒に入る。その1つが **`shp2pgsql`**（シェープ→SQL変換器）。コンテナ内で呼ぶ（`docker exec`）＝自分のパソコンに追加導入不要＝「ゼロ追加」。
  - 但し書き：イメージに binary が含まれるかは実装時 `docker run --rm postgis/postgis which shp2pgsql` で確認。
- **GDAL**＝地理データ読み書きの業界標準エンジン（数百形式を理解・PROJ内蔵で再投影）。**`ogr2ogr`**＝GDAL付属のベクタ変換CLI。**多形式**＝シェープ以外も読める。PostGIS には**同梱されず別途導入が要る重い一式**。

## 5. 3案の手順とコマンド（おおよそ・実フラグは実ファイルで確認）
- **案1 Go**：図形ライブラリで読む→Goで文字コード変換→pgx `CopyFrom` で挿入→`CREATE INDEX`。①〜⑤全部自前＝コード多・周辺が厚い。
- **shp2pgsql（同梱）**：シェープを読んで**SQLを吐き**、`psql` に流す（2段パイプ）。
  ```bash
  shp2pgsql -s 6668 -I -W CP932 N03-23_2023.shp n03_raw | psql "$DB_URL"
  ```
- **ogr2ogr（GDAL）**：シェープを読んで**PostGISへ直接**書き込む（1コマンド）。
  ```bash
  ogr2ogr -f PostgreSQL "PG:dbname=machilens host=localhost" N03-23_2023.shp \
    -nln n03_raw -t_srs EPSG:6668 --config SHAPE_ENCODING CP932 \
    -lco GEOMETRY_NAME=geom -lco SPATIAL_INDEX=GIST
  ```

## 6. なぜハイブリッドか／正規化の中身
①〜⑤（機械的・ツールが解決済み）はツールへ。⑥（本丸＝結合基盤）は SQL/Go に持つ：
```sql
-- 投入後の n03_raw に対して（イメージ）
-- ・N03_007 を5桁コードに整え結合キー化（6桁は末尾落とし＝ADR-0014）
-- ・年度を列で固定 ・上2桁=都道府県コード一致の値域チェック（ADR-0014）
-- → きれいな admin_unit テーブルへ
```
投入ツールを替えても正規化は不変＝継ぎ目（`ADR-0015`・メッシュ移行は `unit_kind` 差し替え）。
