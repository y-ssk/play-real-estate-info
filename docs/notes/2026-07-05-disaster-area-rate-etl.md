# 災害の「該当面積率」を地図に出すまで — 座標・タイル・交差按分をゼロから解説 (2026-07-05)

> **この note のねらい**：洪水などの災害を「区の何％が危険区域に入っているか」で地図に色分けする仕組みを、GIS（地図の計算）を全く知らない人が読んでもレビューできるよう、用語・計算・処理の流れ・目的を一から説明する。実装＝スライス #74（洪水 XKT026）、設計の根拠＝`ADR-0006`（災害＝該当面積率）/`ADR-0015`（交差面積按分）/`ADR-0014`（座標系）/`ADR-0032`（配色）/`ADR-0030`（エリア波）。

---

## 1. この指標が答えたい問い

**「この街（区・市）は、面積のどれくらいが洪水の浸水想定区域に入っているか」** を % で表す。
例：ある区の 45% が浸水想定区域に重なっていれば「洪水該当面積率 = 45%」。地図ではその % を色の濃さで塗る。

- **なぜ「面積率」か**（`ADR-0006`）：浸水の「深さ」や「危険度」を点数化せず、**事実（該当する面積の割合）だけ**を見せる。「5mは0.5mの何倍危険か」のような主観的な重みづけをしない（それは客観性が崩れる）。深さは将来、別の見せ方（塗り絵）で足す。
- **なぜ災害から**：災害は住み替えで誰もが気にする共通土台であり、「面・将来で比べる」という本プロダクトの差別化の核。

---

## 2. 前提の用語（ここだけ読めば以降が分かる）

- **ポリゴン**：地図上の「面（区域）」を、輪郭の点（座標）をつないで表した多角形。**区の形**も**浸水想定区域**も、どちらもポリゴン。
- **座標系（EPSG:6668 / JGD2011）**：地球上の位置を緯度・経度で表す「ものさしの規格」。日本の標準。本プロジェクトは全データをこの規格に統一している（`ADR-0014`）。規格が違うと図形がズレるので、必ず揃える。
- **タイル（z / x / y）**：地図を格子状に区切った1枚1枚の四角。`z`=ズーム（大きいほど拡大＝1枚が狭い）、`x`/`y`=格子の位置。広い範囲を見るには多数のタイルを1枚ずつ集める。
- **GeoJSON**：図形（ポリゴンの座標や属性）をテキストで書いた形式。1タイル分の浸水想定区域が GeoJSON で返る。
- **交差（intersection）**：2つの面が重なっている部分。「区の面」と「浸水想定区域の面」が重なる領域。
- **該当面積率**：`重なった面積 ÷ 区全体の面積 × 100`。＝「区の何％が浸水想定か」。
- **結合（union）**：ばらばらのポリゴンを1つの面にまとめる操作。重なりを溶かして1枚にする。
- **PostGIS**：データベース（PostgreSQL）に「地図の計算」を足した拡張。面積・交差・結合を SQL でできる（`ST_Area` / `ST_Intersection` / `ST_Union`）。

## 3. 全体の流れ（取得 → 格納 → 算出 → 保存 → 表示）

```
[MLIT API]
   │  タイルを1枚ずつダウンロード（約6960枚・§7）
   ▼
[data/xkt026/ の GeoJSON 群]   ← ローカルのファイル
   │  PostGIS へ取り込み
   ▼
[PostGIS: flood_polygon テーブル]  ← 浸水ポリゴンの置き場（新設）
   │  区ごとに 結合→交差→面積 を計算（本丸・§4）
   ▼
[PostGIS: metric_value テーブル]  ← 区ごとの「該当面積率 %」1行
   │  /api/choropleth/values で配信
   ▼
[地図]  ← 青の濃淡で面塗り＋凡例（データなしは色抜き）
```

各段を一言で：

1. **取得**：スクリプトが「1都3県を覆う z14 タイルの座標一覧」を計算し、API から1枚ずつ GeoJSON をダウンロードする（APIキーはヘッダに渡し、値は画面に出さない）。枚数が多く時間がかかるので、サーバに優しく間隔を空ける（レート制御）。
2. **格納**：GeoJSON の浸水ポリゴンを PostGIS の `flood_polygon` テーブルに入れる（座標系6668）。**なぜ入れる？** 面積・交差・結合は PostGIS の計算＝データがデータベースに入っていないと計算できないから。
3. **算出（本丸）**：区ごとに、その区に重なる浸水ポリゴンを集め、**1つに結合（union）してから**区と交差（intersection）し、交差面積を出し、区面積で割って %。
4. **保存**：結果を `metric_value` に1行入れる（区コード・該当面積率・出典・年度）。浸水域が無い区は「**該当なし = 0%**」（値0・状態 present）、取得できていない区は「**データなし**」（状態 none）＝両者を混同させない（`ADR-0011`）。
5. **表示**：フロントが % を取得し、青の濃淡で面塗り。凡例を出す。データなしの区は色を塗らない（基図を透かす）。

## 4. いちばん大事：なぜ「タイル分割ポリゴンの結合」が要るか

これが層1（データの正しさ）の核心。

- タイルは地図を**格子で切る**。だから1つの大きな浸水域が、複数のタイルにまたがって「別々の断片」に切られて届く。
- さらに境界付近では、断片どうしが**わずかに重なる**ことがある（API がサイズの大きいポリゴンを分割提供する都合・XKT026 の注記）。
- もし各断片の交差面積を**単純に足す**と、重なった部分を**二重に数えて**しまう＝面積率が実際より大きくなる（**100% を超える**ことさえある）。

```
      タイル境界
        │
  ▓▓▓▓▓▓│▓▓▓▓        1つの浸水域がタイルで2つの断片に分割
        │
単純合計： ▓▓▓▓▓▓ ＋ ▓▓▓▓ → 境界の重なりを二重計上 → 面積が過大
結合後　： ▓▓▓▓▓▓▓▓▓▓（1枚に溶かす）→ 正しい面積
```

だから、区に関わる浸水ポリゴンを**全部集めて結合（union）で1枚に溶かしてから**面積を測る。**面積率が 0〜100% に収まらない（100超が出る）なら、この結合が漏れているサイン。**

---

## 5. なぜ緯度経度のまま面積を測らないか

- 緯度経度は「度」の単位。日本では**経度1度と緯度1度の実距離が違う**（地球は球だから）。度のまま面積を計算すると歪む。
- PostGIS の **geography 型**は地球を球面として扱い、正しく㎡で測る。既存の「市区町村の面積（area_km2）」も同じ方法。
- ＝面積率の**分子（交差面積）も分母（区面積）も geography で測って割る**。座標系は6668で一貫させる。

## 7. 規模のイメージ（なぜ「重い」のか）

- XKT026 は **z=14〜15 でしか配られない**（API 制約）。面積率のため、広い範囲の**全タイル**が要る（低ズームで粗く取る逃げ道がない）。
- z14 で1都3県（東京・埼玉・千葉・神奈川）＝**約6960枚**。1枚ずつ・サーバに優しく間隔を空けて取ると**約1時間**。
- 参考：人口（XKT013）は z11・**24枚**で済んだ。＝桁違いに多い。洪水は「取得が重い指標」。
- だから取得は**失敗に強く**作る（同じ場所を何度流しても同じ結果になる＝冪等・途中から再開できる）。

---

## 8. レビューの勘所（層1＝ここを見れば正しさが分かる）

- **面積率が 0〜100% に収まっているか**（100超があれば結合漏れ＝二重計上のサイン・§4）。
- 浸水域が無い区が **0%（present）** になっているか（「データなし none」と混ざっていないか・§3-4）。
- 取得できていない区が **none** になっているか。
- 交差・結合・面積が **geography** で測られ、座標系 **6668** で一貫しているか（§5）。
- **出典**（国土数値情報・XKT026・年度）が各行に保持されているか（法的要件・`ADR-0011`）。
