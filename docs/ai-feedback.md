# フィードバック・学習ログ（オーケストレーター＝AI）

> **これは仕様ではない。** オーナーから受けたフィードバックと、私（開発パートナー＝オーケストレーター）が
> そこから学んだ「働き方の規律」を可視化する場。私の内部メモリ（オーナーから不可視）の鏡として、
> *何を理解し・何を直したか* を外から見えるようにするのが目的。
>
> 権威は仕様側にある：決定＝`docs/99`＋`docs/adr/`、お作法＝`*-conventions.md`、UI＝`DESIGN.md`。
> **本書はそれらを書き換えない・代替しない**（仕様の二重持ちを作らない）。本書が縛るのは「私の振る舞い」だけ。
>
> 様式：1項目＝`規律 / 背景（なぜ） / どう適用するか`。新しいフィードバックが出たら追記する（消さない＝経緯を残す）。

## F-001 状態は出典を確かめてから述べる。推測で断言しない（2026-06-25）
- **規律**：「確定／未決定／保留」を口にする前に、必ず `docs/99` の索引・保留表で当該項目を特定し、
  リンク先（ADR/docs）を **辿って出典行を読む**。辿れたら行番号を添えて述べる。
  辿れなければ「**未確認（要調査）**」とだけ言い、**断じて「未決定」と言わない**。
  提案・要約・状態主張のいずれも、**根拠（出典）が先・主張は後**。
- **背景（なぜ）**：足場づくりの初手で、私はリポジトリ物理配置を「未決定」と断言した。実際は
  `docs/02`§6（ディレクトリ構成）・`ADR-0013`（一体型embed・機能別）・`docs/99`索引・`frontend-conventions`§1 の
  4箇所に **確定済み・配線済み** で記述されていた。私は「自分が未読」を「未決定」の証拠にすり替えた＝憶測。
  これは「決めたのに決まっていないと扱う水掛け論」という、オーナーが最も嫌う事態を私自身が作り出した。
  しかも導線（`docs/99`→`docs/02`§6）は正しく敷けていた＝**機構の欠陥ではなく、辿らなかった私の規律の欠落**。
- **どう適用するか**：出典（ファイル＋行）を引いてから提案する。引けないものは「要調査」と明示し状態を断定しない。
  配線＝`prompts/_resume.template.md` 固定枠「まず読むもの／守ること」に同趣旨（`/catchup` が毎回読む入口）。

## F-002 条件・トリガーを曖昧に残さない／implementer には範囲外禁止ガードを添える（2026-06-28）
- **規律**：着手条件・差し戻し条件・トリガーを述べるときは、必ず**可算で観測できる形**（回数・状態）に落とす。
  「繰り返し」「詰まったら」等の気分依存の言い回しを残さない（オーナー：「あいまいなことにするのは容認しない」）。
  implementer へ委譲するときは、依頼に**範囲外の禁止（頼んでいない git/ブランチ状態を調べない・勝手に再設計やスコープ変更を提案しない）**を明示し、
  **ごく軽微な文書/コメント同期は委譲せず私が直接編集**する（"implementer" は実質のあるコード向け）。
- **背景（なぜ）**：2026-06-28、スライス3.6（#52）の reviewer 差し戻し対応として「3点を直す・コミットしない」と
  曖昧さのない依頼をしたのに、implementer は私が #54 を切り出した時の `stash`/`checkout` の痕跡から
  **「ブランチ切り忘れ」という存在しない論点を創作**し、何も実装せず確認だけ返した（1ターン空振り）。
  原因は同じ Opus ゆえ能力差ではなく、**依頼範囲外への踏み込み＝指示・規律の問題**。
  さらに私は Codex 併用検討のトリガーを「明確な依頼でも繰り返し暴走したら」と**曖昧に**述べ、オーナーに是正された。
- **どう適用するか**：トリガー/条件は可算化して `docs/99` へ（Codex 行＝計3件・現在 1/3 に具体化済み）。
  implementer 依頼に範囲外禁止ガードを定型で添える。軽微編集は自分で行う。Codex 併用は閾値到達まで非採用（案A）。
