# XKT015. 国土数値情報（駅別乗降客数）API

> MLIT 不動産情報ライブラリ API の IF 定義（公式マニュアルからの生コピペを構造化したもの）。
> 転記のみ。原文で確認できない項目は「未確認」と明記。実装着手前に本書を最終確認する。

## 1. 概要
- 振り分け: タイル配信（`docs/02_architecture.md` 第3節。XKT 系=GISデータ→タイル/点）。利便性・交通レイヤー
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。XYZ タイル方式で取得
- 取得粒度: **駅の線分（LineString）＝駅の軌道/プラットフォーム区間**（点ではない）。タイル（z/x/y 指定。ズーム 11〜15）。属性フィルタ無し
- 内容: 駅ごとの**乗降客数の時系列（2011〜2023年）**＋運営会社・路線。交通利便性・人の集積の指標
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XKT015?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系）
- 関連: `S12_001g`（グループコード）は **XIT001 取引価格の `station` パラメータ（国土数値情報 駅データ `N02_005g`）と同体系**＝価格と乗降客数を駅で突き合わせ可能

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 11（市）〜15（詳細）で指定可能。値が大きいほど高ズーム |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール参照。z は 11〜15。属性フィルタは無し。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`name` は `passengers_by_station`。`crs` は EPSG:6668）。`geometry.type` は `LineString`（駅区間の線）。タグ命名は `S12_###` コード系。

### 駅の識別・属性
| タグ名 | 内容 | データ型 | データ例 | 備考 |
|---|---|---|---|---|
| S12_001_ja | 駅名 | 文字列型 | 新子安 | |
| S12_001c | 駅コード | 文字列型 | 004562 | |
| S12_001g | グループコード | 文字列型 | 004562 | **XIT001 の駅コード（`N02_005g`）と同体系**。同一駅の集約キー |
| S12_002_ja | 運営会社 | 文字列型 | 東日本旅客鉄道 | |
| S12_003_ja | 路線名 | 文字列型 | 東海道線 | |
| S12_004 | 鉄道区分 | 文字列型 | 11 | コード値。**出力例では `"11.0"` と小数表記の文字列**（IF表は `11`）＝要パース・要確認 |
| S12_005 | 事業者種別 | 文字列型 | 2 | コード値（出力例 `"2.0"`。同上） |

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XKT015?response_format=geojson&z=14&x=14547&y=6462" > XKT015.geojson
```
