# XPT001. 不動産価格（取引価格・成約価格）情報のポイント (点) API

> MLIT 不動産情報ライブラリ API の IF 定義（公式マニュアルからの生コピペを構造化したもの）。
> 転記のみ。原文で確認できない項目は「未確認」と明記。実装着手前に本書を最終確認する。

## 1. 概要
- 振り分け: **両用**（`docs/02_architecture.md` 第3節。XPT=点 GeoJSON→ETL/タイルの両用）
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。点（Point）。XYZ タイル方式で取得
- 取得粒度: **点（Point）＝対象不動産の「最寄り駅」のポイント**（物件の実位置ではない）。タイル（z/x/y 指定。ズーム 11〜15）＋取引時期 `from`/`to` で絞り込み
- **重要な性質（原文注記）**: 返却される点は対象不動産の**最寄り駅**のポイント。そのため**同一のポイントに複数の不動産価格情報が含まれる場合がある**（＝点は物件位置ではなく駅位置。地図表現・集計で前提にする）
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XPT001?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系）
- 関連: 同じ取引価格データの JSON 版が `XIT001`（ETL）。本APIは点版。**XIT001 とフィールド体系・値表現が異なる**（後述）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 11（市）〜15（詳細）で指定可能。値が大きいほど高ズーム（カバー領域は狭い） |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |
| from | 取引時期From | YYYYN（数字5桁） | ○ | YYYY=西暦, N=四半期(1:1-3月/2:4-6月/3:7-9月/4:10-12月)。取引価格は `20053`〜、成約価格は `20211`〜 |
| to | 取引時期To | YYYYN（数字5桁） | ○ | 同上 |
| priceClassification | 価格情報区分コード | NN（数字2桁） | 任意 | 01=不動産取引価格情報のみ / 02=成約価格情報のみ / 未指定=両方 |
| landTypeCode | 種類コード | NN（数字2桁） | 任意 | 01=宅地(土地) / 02=宅地(土地と建物) / 07=中古マンション等 / 10=農地 / 11=林地 / 未指定=すべて。複数指定はカンマ区切り（例: `landTypeCode=01,02,07`） |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール（上記参照URL）を参照。z は 11〜15。
- `from`/`to` は必須。期間の下限は価格区分で異なる（取引価格 `20053` / 成約価格 `20211`）。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`。**`name` が配列 `["station", "real_estate_price"]`**（駅レイヤー＋不動産価格の合成を示唆）。`crs` は EPSG:6668。
- `geometry.type` は `Point`（最寄り駅の座標）。同一座標に複数 Feature（＝複数の価格レコード）が並びうる。
- タグ命名は snake_case＋`_ja` サフィックス。**値はすべて整形済みの表示用文字列**（例: `4,000万円`・`90㎡`・`1999年`・全角 `３ＬＤＫ`）＝XIT001 の生値（`85000000`・`80`）と対照的。全て文字列型。

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XPT001?response_format=geojson&z=14&x=14624&y=6016&from=20252&to=20252" > XPT001.geojson
```

## 5. MachiLens 取り込み観点（実装・レビューの足場）
> 着手段階で AI が記入する欄。空欄は「未検討」。価格＝結果指標（本丸の一角）。
- 振り分け方針: 両用（`docs/02`§3）。点が「最寄り駅」位置のため、**物件の実位置としては使えない**。市区町村/地区単位の集計（中央値・分布）に使うのが自然。生の点表示は「駅に集約された価格」の意味を UI で明示する必要。
- 取り込み対象フィールド / PostGIS マッピング: 未検討（`city_code`/`district_code`＋価格。点＝`POINT` だが駅位置。**XIT001(JSON生値)と同じ取引データの別表現＝どちらを ETL の正とするか要判断**）
- 一意キー（冪等性の判定キー）: 未検討（同一点・同一区分に複数レコードがあり点座標では一意化不可。XIT001 同様レコード単位の一意キーが乏しい）
- 値域・整合チェック（層1）: 未検討（**値が整形済み文字列**＝`4,000万円`/`90㎡` のパースが必須。負値・桁・単位の検証、`city_code` 5桁、`from`/`to` 範囲）
- 欠損の扱い（"データなし" の判定と UI 表示への接続）: 未検討（多数の項目が空文字。空＝未入力の扱い）
- 出典の保持（MLIT 出典の紐づけ＝法的要件）: 未検討
- レート制御メモ（連続実行を避ける）: 未検討
- 未確認・要確認事項:
  - 転記元の公式ドキュメント URL
  - gzip エンコードの要否（原文に記載なし）
  - 整形済み文字列値（`万円`/`㎡`/全角）のパース仕様。XIT001 の生値とどちらを ETL 入力にするか
