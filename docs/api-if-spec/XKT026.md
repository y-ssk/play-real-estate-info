## 1. 概要
- 振り分け: タイル配信（`docs/02_architecture.md` 第3節。XKT 系=GISデータ→多くがタイル配信。防災コアの中心レイヤー）
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。XYZ タイル方式で取得
- 取得粒度: タイル（z/x/y 指定。ズーム 14〜15）
- 注記（原文）: 一部のサイズが大きいポリゴンや複雑なポリゴンは分割して提供しているため、原典データと形状が一致しない場合がある
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XKT026?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系。`docs/02` 第9節「JGD2011前提」と整合）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 14（丁目）〜15（詳細）で指定可能。値が大きいほど高ズーム（カバー領域は狭い） |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール（上記参照URL）を参照。
- z は 14〜15 のみ指定可能。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`response_format=geojson` の場合）。`response_format=pbf` ではバイナリベクトルタイル。
```
{ "type": "FeatureCollection", "name": "flood_area_maximum_scale", "crs": {...EPSG:6668...}, "features": [ { "type":"Feature", "geometry": {...}, "properties": {...} } ] }
```

各 Feature の `properties`（タグ）:

| タグ名 | 内容 | データ型 | データ例 | 備考 |
|---|---|---|---|---|
| A31a_201 | 河川番号 | 文字列型 | 8404090001 | |
| A31a_202 | 河川名 | 文字列型 | 庄川 | |
| A31a_203 | 河川管理番号 | 文字列型 | 84 | |
| A31a_204 | 河川管理者 | 文字列型 | 北陸地方整備局 | |
| A31a_205 | 浸水深ランク | 整数型 | 1 | ※XIT系と異なり数値型。意味（ランク値の対応表）は原典データ項目ページ参照（未確認） |

- ※ 出力例の `properties` には上記5項目に加え、**IF表に無いフィールド `_id`（例: `1JpogpkB2Vp85Hbx6M82`）・`_index`（例: `bs030_flood_area_maximum_scale_chubu_202509251934`）が含まれる**（要確認＝文書化されていない内部フィールド。取り込み時に依存しない方が安全）。
- `geometry` は `Polygon`（複数リング＝穴あき/分割あり）。座標系は CRS（EPSG:6668）。

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XKT026?response_format=geojson&z=14&x=14432&y=6392" > XKT026.geojson
```
