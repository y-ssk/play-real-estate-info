# XPT002. 地価公示・地価調査のポイント (点) API

> MLIT 不動産情報ライブラリ API の IF 定義（公式マニュアルからの生コピペを構造化したもの）。
> 転記のみ。原文で確認できない項目は「未確認」と明記。実装着手前に本書を最終確認する。

## 1. 概要
- 振り分け: **両用**（`docs/02_architecture.md` 第3節。XPT=点 GeoJSON→ETL/タイルの両用）
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。点（Point）。XYZ タイル方式で取得
- 取得粒度: **点（Point）＝地価公示・地価調査の標準地/基準地**（XPT001 の「最寄り駅」点とは異なり、地点そのもの）。タイル（z/x/y）＋対象年 `year` で絞り込み
- 対象データ: 国土交通省地価公示 ＋ 都道府県地価調査（`priceClassification` で選択）。`docs/01` の「取得できるのは公的地価のみ。相続税/固定資産税路線価は別系統」と整合
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XPT002?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | **13（大字）〜15（詳細）** で指定可能。値が大きいほど高ズーム |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |
| year | 対象年 | NNNN（数字4桁） | ○ | 1995〜最新年（公開時点では2024）。**一つのみ指定可** |
| priceClassification | 地価情報区分コード | N（数字1桁） | 任意 | 0=国交省地価公示のみ / 1=都道府県地価調査のみ / 未指定=両方 |
| useCategoryCode | 用途区分コード | NN（数字2桁） | 任意 | 00=住宅地 / 03=宅地見込地 / 05=商業地 / 07=準工業地 / 09=工業地 / 10=市街化調整区域内の現況宅地 / 13=同・現況林地(公示のみ) / 20=林地(調査のみ) / 未指定=すべて。複数指定はカンマ区切り |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール参照。z は 13〜15。`year` は単年・必須。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`name` は `land_prices`、`crs` は EPSG:6668）。`geometry.type` は `Point`（地点座標）。
- タグ命名は snake_case。多くに `_ja`／`u_`（単位込み整形値）プレフィクス。**型が混在**（整数型/文字列型/真偽型）。
- **値表現の非対称**: 当年価格 `u_current_years_price_ja` は整形文字列 `3,100,000(円/㎡)`、前年価格 `last_years_price` は整数生値 `2820000`。同種でも片方は整形・片方は生値（取り込みで個別対応）。
- 粒度フィールドと**連結文字列フィールドが併存**（例: `front_road_*` 個別 と `front_road_condition`「北 20.0m 市区町村道」）。

## 5. MachiLens 取り込み観点（実装・レビューの足場）
> 着手段階で AI が記入する欄。空欄は「未検討」。価格＝結果指標（本丸の一角）。地価は「公的・継続的」で街の素性指標に向く。
- 振り分け方針: 両用（`docs/02`§3）。地点が標準地/基準地＝**継続観測点**で経年比較が可能（`_index` の `2011-2025`、`last_years_price`/`year_on_year_change_rate`）。市区町村/地区の地価水準・変動の指標化に有用。
- 取り込み対象フィールド / PostGIS マッピング: 未検討（`point_id` を主キー、`POINT` ジオメトリ。整形値は別途数値カラムへパース）
- 一意キー（冪等性の判定キー）: 未検討（候補: `point_id`＋`year`。XPT001 より一意化しやすい）
- 値域・整合チェック（層1）: 未検討（`u_current_years_price_ja`/`u_cadastral_ja`/`u_regulations_*` の単位込み文字列パース、`last_years_price` は非負整数、`year_on_year_change_rate` の符号/範囲、`prefecture_code`2桁/`city_code`5桁、`*_availability` は真偽）
- 欠損の扱い（"データなし" の判定と UI 表示への接続）: 未検討（多数項目が空文字）
- 出典の保持（MLIT 出典の紐づけ＝法的要件）: 未検討（公示/調査の区分＝`land_price_type`/`priceClassification`）
- レート制御メモ（連続実行を避ける）: 未検討
- 未確認・要確認事項:
  - 転記元の公式ドキュメント URL／原典 NLNI（L01/L02）の項目コード定義
  - gzip エンコードの要否（原文に記載なし）
  - 整形値（`万円`系はXPT001／本APIは `円/㎡`・`㎡`・`%`）のパース仕様。当年=整形文字列／前年=生整数の非対称の扱い
  - `use_category_name_ja` の表記差（IF表 `4,商業地` vs 出力 `商業地`）
  - コード値（`land_price_type`/`front_road_pavement_condition`/`proximity_to_transportation_facilitites`/`pause_flag`）の定義
  - `front_road_width` の単位
  - 連結文字列フィールド（`location`/`shape`/`front_road_condition`/`side_road_condition`）と個別フィールドの重複の扱い
  - `_id`/`_index` の位置づけ（XPT001 に無く XPT002 に有る差）
