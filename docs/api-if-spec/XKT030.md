## 1. 概要
- 提供元: 都市計画決定GISデータ（XKT001/002/003/014/023/024 と同系統）
- 振り分け: タイル配信（`docs/02_architecture.md` 第3節。XKT 系=GISデータ→タイル配信。規制・都市計画レイヤー）
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。XYZ タイル方式で取得
- 取得粒度: **都市計画道路の線形（MultiLineString）**＝この系統で初のライン主体。タイル（z/x/y 指定。ズーム 11〜15）。属性フィルタ無し
- 内容: 都市計画の**都市計画道路**（広場を含む）。計画道路の有無は周辺の将来変化（拡幅・新設）に関わる
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XKT030?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 11（市）〜15（詳細）で指定可能。値が大きいほど高ズーム |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール参照。z は 11〜15。属性フィルタは無し。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`name` は `city_planning_road`。`crs` は EPSG:6668）。
- `geometry.type` は **`MultiLineString`**（道路の線形。区域系と異なりライン）。
- タグ命名は説明的 snake_case。`city_code`（XKT001/002/014 と同様）＋`decision_type_ja`（XKT023/024 と同様）の混成。`kubun_id` は整数型。

各 Feature の `properties`（タグ）:

| タグ名 | 内容 | データ型 | データ例 | 備考 |
|---|---|---|---|---|
| planning_road_ja | 都市計画道路種類名 | 文字列型 | 都市計画道路 | `kubun_id` の名称 |
| kubun_id | 区分コード | 整数型 | 3011 | **原文にインライン凡例: 3011=都市計画道路 / 3023=広場**（他値は原典参照・要確認） |
| prefecture | 都道府県名 | 文字列型 | 栃木県 | |
| city_code | 市区町村コード | 文字列型 | 09361 | 5桁 |
| city_name | 市区町村名 | 文字列型 | 壬生町 | |
| first_decision_date | 当初決定日 | 文字列型 | （空） | |
| decision_date | 設定年月日 | 文字列型 | 1964/11/25 | **`YYYY/MM/DD`**（最終告示日。XKT014/023/024 の和暦と異なり西暦スラッシュ＝同系統でも日付表記が不統一） |
| decision_type_ja | 設定区分名 | 文字列型 | （空） | |
| decision_maker | 設定者名 | 文字列型 | （空） | |
| notice_number_s | 告示番号S | 文字列型 | （空） | 告示番号（当初） |
| notice_number | 告示番号 | 文字列型 | （空） | 告示番号L（告示番号（最終）） |

- ※ 出力例の `properties` には IF表に無い内部フィールド **`_id`・`_index`（例: `bs035_city_planning_road_202508061457`）が含まれる**（要確認＝未文書・依存しない方が安全）。並び順は IF 表順と不一致（キー名参照が前提）。

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XKT030?response_format=geojson&z=11&x=1828&y=751" > XKT030.geojson
```
レスポンス例（GeoJSON。座標列が膨大なため `coordinates` は中略。`MultiLineString` の Feature を示す）:
```
{
  "type": "FeatureCollection",
  "name": "city_planning_road",
  "crs": { "type": "name", "properties": { "name": "urn:ogc:def:crs:EPSG::6668" } },
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "MultiLineString",
        "coordinates": [ [ [139.80222433805466, 36.4212716521386], ... ], [ ... ] ]

      "properties": {
        "_id": "bl33fZgB8M1gMx8KUF0W",
        "_index": "bs035_city_planning_road_202508061457",
        "planning_road_ja": "都市計画道路",
        "kubun_id": 3011,
        "prefecture": "栃木県",
        "city_code": "09361",
```
