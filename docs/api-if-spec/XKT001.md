# XKT001. 都市計画決定GISデータ（都市計画区域/区域区分）API

> MLIT 不動産情報ライブラリ API の IF 定義（公式マニュアルからの生コピペを構造化したもの）。
> 転記のみ。原文で確認できない項目は「未確認」と明記。実装着手前に本書を最終確認する。

## 1. 概要
- 提供元: 都市計画決定GISデータ（国土数値情報とは別系統の出典表記）
- 振り分け: タイル配信（`docs/02_architecture.md` 第3節。XKT 系=GISデータ→タイル配信。規制・都市計画レイヤー）
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。XYZ タイル方式で取得
- 取得粒度: 区域ポリゴン。タイル（z/x/y 指定。ズーム 11〜15）。属性フィルタ無し
- 内容: **1つのAPIで2系統のデータが混在**＝「都市計画区域」(`_index` 例 `bs010_urban_plan_area`)と「区域区分」(`_index` 例 `bs022_area_classification`＝市街化区域/調整区域)。`kubun_id` で識別（観測値 21=都市計画区域 / 22=市街化区域、他は原典参照・要確認）
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XKT001?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 11（市）〜15（詳細）で指定可能。値が大きいほど高ズーム |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール参照。z は 11〜15。属性フィルタは無し。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`name` は `urban_plan_area, area_classification`＝2系統の複合を示す）。`crs` は EPSG:6668。
- `geometry.type` は **`Polygon` と `MultiPolygon` が混在**。
- タグ命名は説明的 snake_case。`kubun_id`（整数）で都市計画区域/区域区分のレコード種別を識別。
- 告示・決定系フィールドは出力例ではほぼ空（要確認＝データ整備状況）。

各 Feature の `properties`（タグ）:

| タグ名 | 内容 | データ型 | データ例 | 備考 |
|---|---|---|---|---|
| prefecture | 都道府県名 | 文字列型 | 北海道 | |
| city_code | 市区町村コード | 文字列型 | 01100 | 5桁 |
| city_name | 市区町村名 | 文字列型 | 札幌市 | |
| kubun_id | 区分コード | 整数型 | 21 | コード値（観測: 21=都市計画区域 / 22=市街化区域。全定義は原典参照・要確認） |
| decision_date | 設定年月日 | 文字列型 | （空） | 最終告示日 |
| decision_classification | 設定区分 | 文字列型 | （空） | |
| decision_maker | 設定者名 | 文字列型 | （空） | |
| notice_number | 告示番号 | 文字列型 | （空） | 告示番号L（告示番号（最終）） |
| area_classification_ja | 区域区分 | 文字列型 | 都市計画区域 / 市街化区域 | レコードの区域種別名 |
| first_decision_date | 当初決定日 | 文字列型 | （空） | |
| notice_number_s | 告示番号S | 文字列型 | （空） | 告示番号（当初） |

- ※ 出力例の `properties` には IF表に無い内部フィールド **`_id`・`_index` が含まれる**。**`_index` がレコードの出所データを示す**（`bs010_urban_plan_area…`＝都市計画区域 / `bs022_area_classification…`＝区域区分）＝実質的に2データセットの合成。要確認＝未文書だが識別に有用。
- ※ プロパティ並び順は IF 表順と不一致（キー名参照が前提）。

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XKT001?response_format=geojson&z=14&x=14626&y=6020" > XKT001.geojson
```
