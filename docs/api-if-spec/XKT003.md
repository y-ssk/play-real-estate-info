# XKT003. 都市計画決定GISデータ（立地適正化計画）API

> MLIT 不動産情報ライブラリ API の IF 定義（公式マニュアルからの生コピペを構造化したもの）。
> 転記のみ。原文で確認できない項目は「未確認」と明記。実装着手前に本書を最終確認する。

## 1. 概要
- 提供元: 都市計画決定GISデータ（XKT001/002 と同系統）
- 振り分け: タイル配信（`docs/02_architecture.md` 第3節。XKT 系=GISデータ→タイル配信。規制・都市計画レイヤー）
- 形式: GISデータ（GeoJSON / バイナリベクトルタイル pbf）。XYZ タイル方式で取得
- 取得粒度: 区域ポリゴン。タイル（z/x/y 指定。ズーム 11〜15）。属性フィルタ無し
- 内容: **立地適正化計画**の区域（コンパクトシティ施策。居住誘導区域・都市機能誘導区域等を含む計画）。「街の将来の都市構造」を示す
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XKT003?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: 原文に gzip/`--compressed` の記載なし（使用例にもオプションなし）。要確認
- 座標系: 出力例の CRS は `urn:ogc:def:crs:EPSG::6668`（JGD2011 地理座標系）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 11（市）〜15（詳細）で指定可能。値が大きいほど高ズーム |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール参照。z は 11〜15。属性フィルタは無し。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`name` は `location_optimize_plan_area`。`crs` は EPSG:6668）。`geometry.type` は `Polygon`（出力例）。タグ命名は説明的 snake_case。

各 Feature の `properties`（タグ）:

| タグ名 | 内容 | データ型 | データ例 | 備考 |
|---|---|---|---|---|
| prefecture | 都道府県名 | 文字列型 | 静岡県 | |
| city_code | 行政区域コード | 文字列型 | 22222 | 5桁（IF表の内容は「行政区域コード」。XKT001/002 の `city_code`=市区町村コードと同義） |
| city_name | 市区町村名 | 文字列型 | 伊豆市 | |
| decision_date | 区域設定年月日 | 文字列型 | （空） | 最終告示日 |
| decision_classification | 設定区分 | 文字列型 | （空） | |
| decision_maker | 設定者名 | 文字列型 | （空） | |
| notice_number | 告示番号 | 文字列型 | （空） | 告示番号L（告示番号（最終）） |
| kubun_id | 区域コード | 整数型 | 0 | コード値（観測: 0=立地適正化計画区域。居住誘導/都市機能誘導等の他値は原典参照・要確認） |
| kubun_name_ja | 区域名 | 文字列型 | 立地適正化計画区域 | `kubun_id` の名称 |
| area_classification_ja | 区域区分 | 文字列型 | 立地適正化計画区域 | 例では `kubun_name_ja` と同値（使い分けは要確認） |
| first_decision_date | 当初決定日 | 文字列型 | （空） | |
| notice_number_s | 告示番号S | 文字列型 | （空） | 告示番号（当初） |

- ※ 出力例の `properties` には IF表に無い内部フィールド **`_id`・`_index`（例: `bs011_location_optimiz_plan_area_202511181144`。`_index` は `optimiz` と綴り）が含まれる**（要確認＝未文書・依存しない方が安全）。並び順は IF 表順と不一致（キー名参照が前提）。

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XKT003?response_format=geojson&z=14&x=14507&y=6496" > XKT003.geojson
```
