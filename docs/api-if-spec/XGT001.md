## 1. 概要
- 提供元: **国土地理院**（出典表示の文言が他レイヤーと異なる）

- データ鮮度（原文注記）: **配信データは原典データの更新を常に反映していない**。更新はお知らせ欄を確認。最新・詳細は当該市町村に確認のこと（＝鮮度の限界を UI/運用で明示する必要）

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| response_format | 応答形式 | geojson / pbf | ○ | geojson…GeoJSON応答 / pbf…バイナリベクトルタイル応答 |
| z | ズームレベル（縮尺） | 整数 | ○ | 11（市）〜15（詳細）で指定可能。値が大きいほど高ズーム（カバー領域は狭い） |
| x | タイル座標のX値 | 整数 | ○ | XYZ方式のX値 |
| y | タイル座標のY値 | 整数 | ○ | XYZ方式のY値 |

制約（※注記）:
- XYZ方式の詳細は GSI の確認ツール（上記参照URL）を参照。
- z は 11〜15 で指定可能。属性フィルタは無し。

## 3. レスポンス（出力）
包み構造: GeoJSON `FeatureCollection`（`response_format=geojson` の場合。例の `name` は `evacuation_facilities`）。`response_format=pbf` ではバイナリベクトルタイル。
- **`geometry.type` は `Point`（防災コアで初の点データ）**。座標は `[lng, lat]` の単一ペア。
- タグ命名は説明的 snake_case。**災害種別ごとの対応可否が `*_flag`（真偽型＝boolean）で並ぶ**＝他の防災レイヤー（区域）が「危険の面」、本APIは「避難先の点＋対応災害」。

各 Feature の `properties`（タグ）:

| タグ名 | 内容 | データ型 | データ例 | 備考 |
|---|---|---|---|---|
| common_id | 共通ID | 文字列型 | E1320100151201 | 施設の共通ID（`E`＋数字）。一意キー候補 |
| prefecture_and_city | 都道府県名及び市町村名 | 文字列型 | 東京都八王子市 | 都道府県＋市区町村が**連結された1フィールド**（分割なし） |
| facility_name_ja | 施設・場所名 | 文字列型 | 清水公園 | `_ja` サフィックス |
| address_ja | 住所 | 文字列型 | 東京都八王子市犬目町143-2 | `_ja` サフィックス。例により市町村までのみのデータもあり |
| flood_flag | 洪水 | 真偽型 | false | **boolean 型（新）** |
| landslide_flag | 崖崩れ、土石流及び地滑り | 真偽型 | false | boolean |
| high_tide_flag | 高潮 | 真偽型 | false | boolean |
| earthquake_flag | 地震 | 真偽型 | true | boolean |
| tsunami_flag | 津波 | 真偽型 | false | boolean |
| large_fire_flag | 大規模な火事 | 真偽型 | false | boolean |
| inland_flooding_flag | 内水氾濫 | 真偽型 | false | boolean |
| volcanic_phenomenon_flag | 火山現象 | 真偽型 | false | boolean |
| same_address_flag | 指定避難所との住所同一 | 真偽型 | false | boolean |
| remarks | 備考 | 文字列型 | 想定収容人数：地震（屋外）18136人 | 自由文（収容人数・所在地補足等が混在） |

- ※ 8つの災害種別フラグ（洪水/土砂/高潮/地震/津波/大火/内水/火山）は、防災ハザードレイヤー（XKT026 洪水・027 高潮・028 津波・029 土砂 …）と意味的に対応＝「この危険に対してどの避難場所が有効か」の突き合わせに使える。
- ※ 出力例の `properties` には上記に加え、IF表に無い内部フィールド **`_id`・`_index`（例: `bi001_evacuation_facilities_202509161156`）が含まれる**（防災系共通。要確認＝未文書・依存しない方が安全）。並び順は IF 表順と不一致（キー名参照が前提）。

## 4. 使用例
リクエスト（Windows コマンドプロンプト。GeoJSON取得）:
```
curl -H "Ocp-Apim-Subscription-Key:{発行されたAPIキー}" "https://www.reinfolib.mlit.go.jp/ex-api/external/XGT001?response_format=geojson&z=11&x=1786&y=816" > XGT001.geojson
```

## 5. MachiLens 取り込み観点（実装・レビューの足場）
> 着手段階で AI が記入する欄。空欄は「未検討」。防災コア＝本丸（危険の「面」に対する避難先の「点」）。
- 振り分け方針: 点データ＝`docs/02`§3 では XPT が「両用」だが本APIは XGT（タイル）。施設点を市区町村単位でカウント/最寄り計算するなら ETL/両用が自然（`docs/99` 保留「防災レイヤーの扱い」/ P2）。
- 取り込み対象フィールド / PostGIS マッピング: 未検討（点＝`POINT` ジオメトリ。`*_flag` は boolean カラム、`_id`/`_index` は非依存）
- 一意キー（冪等性の判定キー）: 未検討（候補: `common_id`＝施設共通ID。一意性が高そう＝他の防災レイヤーより明快）
- 値域・整合チェック（層1）: 未検討（`*_flag` は真偽、`common_id` 形式、座標が日本範囲内、`prefecture_and_city` の整合）
