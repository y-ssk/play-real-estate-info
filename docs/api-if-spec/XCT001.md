# XCT001. 鑑定評価書情報API

> MLIT 不動産情報ライブラリ API の IF 定義（公式マニュアルからの生コピペを構造化したもの）。
> 転記のみ。原文で確認できない項目は「未確認」と明記。実装着手前に本書を最終確認する。

## 1. 概要
- 振り分け: ETL（`docs/02_architecture.md` 第3節。XCT=属性JSON→ETL）
- 形式: JSON（gzip エンコード。クライアントでのデコードが必要な場合あり）
- 取得粒度: 鑑定評価書レコード（標準地/基準地単位。`year`/`area`/`division` で絞り込み）
- 内容: 地価公示・地価調査の**鑑定評価書**の詳細（標準地の属性・法規制・鑑定評価手法ごとの価格内訳まで）。**全109項目・すべて文字列型**
- エンドポイント: `https://www.reinfolib.mlit.go.jp/ex-api/external/XCT001?<パラメータ>`
- 認証: ヘッダ `Ocp-Apim-Subscription-Key: <APIキー>`（キーは環境変数 `MLIT_API_KEY`。**AIは値に触れない**）
- エンコード: gzip（`curl` は `--compressed`）
- 位置情報: **`緯度`/`経度` を文字列で含む**（GeoJSON ではないが地図化可能）。座標系の明記なし（要確認。`緯度=26.24…`/`経度=127.67…` ＝十進度）
- 関連: 地価の点版は `XPT002`。本APIは同じ標準地の鑑定評価「中身」。`公示価格`・`変動率` も含み XPT002 と相互参照可能

## 2. リクエストパラメータ
| パラメータ | 内容 | 形式 | 必須 | 備考 |
|---|---|---|---|---|
| year | 価格時点 | YYYY（数字4桁） | ○ | 2022〜2026（最新年から5年分のみ） |
| area | 都道府県コード | NN（数字2桁） | ○ | 複数指定はカンマ区切り（原文例は `prefectureCode=09,10` ＝パラメータ名の表記ゆれ、XIT001 と同じ。要確認）。コード詳細は XIT002 ＜参考＞ |
| division | 用途区分 | NN（数字2桁） | ○ | 00=住宅地 / 03=宅地見込地 / 05=商業地 / 07=準工業地 / 09=工業地 / 10=調整区域内宅地 / 13=現況林地 / 20=林地(都道府県地価調査) |

制約（※注記）:
- `year`/`area`/`division` はすべて必須。`year` は最新5年分のみ。

## 3. レスポンス（出力）
包み構造: `{ "status": "OK", "data": [ { ... }, ... ] }`（gzip エンコード）。
- 各要素は**フラットなオブジェクト**。キーは**全角/半角スペース区切りの日本語階層ラベル**（例: `標準地 法令上の規制等 その他 高度地区1 高度`）。**全項目が文字列型**（数値・座標・0/1フラグも文字列）。
- ⚠ **IF表のタグ名と JSON 実キーに差異**: 例 `標準地番号 用途区分コード`(表)→`標準地番号 用途区分`(JSON), `… 構造コード`→`… 構造`, `指定建蔽率`→`指定建ぺい率`。また表は全角スペース「　」、JSON 例は半角/単一スペース。**取り込みは実JSONキーで参照**し、項目定義は参考CSVで確定すること（要確認）。

## 5. MachiLens 取り込み観点（実装・レビューの足場）
> 着手段階で AI が記入する欄。空欄は「未検討」。価格＝結果指標（本丸の一角）。鑑定評価書は最も詳細だが MVP では過剰な可能性大。
- 振り分け方針: ETL（`docs/02`§3）。ただし**項目が極めて多くMVPで全量は不要**。当面は `1㎡当たりの価格`・`公示価格`・`変動率`・`緯度/経度`・用途区分・所在地など中核のみ取り込む想定（取捨は P2/価格レイヤー設計）。
- 取り込み対象フィールド / PostGIS マッピング: 未検討（`緯度`/`経度`→`POINT` 化可能。キーは日本語ラベル＝**実JSONキー（半角スペース）で参照**し、項目定義は参考CSVで確定）
- 一意キー（冪等性の判定キー）: 未検討（候補: `標準地番号`系（県コード＋市区町村コード＋地域名＋用途区分＋連番）＋`価格時点`）
- 値域・整合チェック（層1）: 未検討（**全文字列**＝数値/座標のパース必須。`0`/`""` の「該当なし」判定、価格は非負、緯度経度の範囲、`供給処理施設` の 0/1）
- 欠損の扱い（"データなし" の判定と UI 表示への接続）: 未検討（空文字・`0` が多数。記載無しコード（「（記載無含）」表記）の扱い）
- 出典の保持（MLIT 出典の紐づけ＝法的要件）: 未検討（鑑定評価書＝公示/調査由来）
- レート制御メモ（連続実行を避ける）: 未検討（`area`×`division`×`year` でループ。件数は限定的）
- 未確認・要確認事項:
  - 転記元の公式ドキュメント URL／**参考CSV同梱の項目定義**（109項目の正確な意味・コード）
  - IF表タグ名と JSON 実キーの差異（`用途区分コード`/`構造コード`/`指定建蔽率` 等、全角/半角スペース）
  - `緯度`/`経度` の測地系（他APIは EPSG:6668＝JGD2011。本APIは明記なし）
  - `0`/`""` がリテラル値か「該当なし」かの区別
  - `area` パラメータ名の表記ゆれ（原文例 `prefectureCode`。XIT001 と同根の要確認）
  - `相続税路線価` の位置づけ（`docs/01` の「路線価は別系統・非取得」と、本書に同梱される参照値の関係）
  - MVP で取り込む項目の取捨（全109は過剰）＝価格レイヤー設計時に決定
