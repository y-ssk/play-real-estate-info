# ADR-0005: 指標化の高度 — 事実ベースの素の数値を土台に「見て分かる」を重ねる

- ステータス: 承認
- 日付: 2026-06-24
- 関連: `docs/99`（バックログ優先1・価値定義）/ `docs/01`§3・§5 / `docs/02`§3・§8 / `ADR-0004`

## なぜ（背景・課題）

価値定義（バックログ優先1）の起点として、MVPで街の素性を「どの高度で数値化し、どこまで束ねるか」を決める必要があった。
`docs/01` の価値提案は「街の素性を数値化し束ねて面で比べる」だが、同じ `docs/01` のMVPスコープは「スコアリング・重みづけUIはやらない（→v2）」。
この一見の緊張（束ねる vs 点数化しない）を解かないと、下流（各分野の指標・カルテ・比較体験）が定まらない。

## 結論（決定）

**事実ベースの素の数値を必ず保持し（案A）、それを「一目で分かる地図の見せ方」に落とす（案Cの発想）。複数分野を混ぜた点数化（案B）はしない。**

固める原則：

1. **色は「単一指標の数値の大小」を表す。「良し悪しの点数」ではない。**
   地図の塗りは一つの指標の数値そのもの（地価の高安・人口の増減など）を濃淡で見せるだけ。複数分野を混ぜて一色にする＝それがスコアリングなのでやらない。結果として、見せ方は「分野ごとに塗りを切り替える／重ねる」になる。
2. **見せ方は2層に役割分担し、市区町村単位を保つ。**
   - 面で塗る層（集計値）：浸水域の面積率・地価の代表値・人口増減率などを市区町村ごとに集計し、その数値を濃淡で塗る。← 単位は市区町村のまま。直感で見たい人向け。
   - 生データを重ねる層（塗り絵）：浸水想定区域のポリゴンや駅・学校の点など、市区町村に丸めず地図に重ねる詳細。← 市区町村単位を置き換えず、その上に重ねる。
3. **比較データはMVP、比較UIはv1。** 市区町村ごとの集計データはMVPで持つ（v1の横並び比較が読む）。横に並べて見せるUIの意匠はv1で、実物を見ながら別途検討する。

## 検討した代替案と捨てた理由

- **案B（分野内だけ等級/相対値に正規化）** … 「面で比べる」は直感的になるが、「何を5にするか」の基準が恣意になりやすく、分野内合成も実質スコアリングに滑りv2との線引きが曖昧化する。MVPの芯（自分で調べ判断）とスコープから外れる懸念。慎重に扱うべきで、MVPでは採らない。
- **案C単独（指標化を最小限にしレイヤー重ね合わせのみ）** … ETL負担は最小だが、市区町村を横並びで比べる力が弱く、差別化の核（面・束ね）が立たない。Cの発想は案Aの上に「見せ方」として重ねる形で活かす。
- **案A単独（素の数値を並べるだけ・可視化を作り込まない）** … 透明性は高いが「一目で分かる」即時性に欠ける。可視化（Cの発想）を重ねて補う。

## 影響（結果・トレードオフ）

- ETLは市区町村単位の集計（素の数値）を持てばよく、本丸を薄く保てる。層1検証（データの正しさ）も素の数値ベースで単純。
- 地図は「分野ごとの単一指標を塗る／生レイヤーを重ねる」構成になり、UIに分野切替の仕掛けが要る（DESIGN側の論点）。
- 「直感で見たい人／じっくり読み込みたい人」の両方を、2層＋カルテで受け止める。ペルソナは未確定だが「自分だったら」をMVPの出発点とする（`docs/99` に保留登録）。
- 残論点：各分野を具体的に何の数値で表すか（次ブロック）、集計の定義（面積率の取り方等）、比較ビューの見せ方（v1）。
