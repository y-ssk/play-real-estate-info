# ADR-0022: N03境界の投入機構＝ハイブリッド（投入＝shp2pgsql／正規化＝SQL・Go）
- ステータス: 承認
- 日付: 2026-06-25
- 関連: `docs/99_decision-register.md`（保留→確定「N03ロード機構・取得自動化」・足場/ETL入口）／**お作法の最新は `docs/backend-conventions.md` §5**（本ADRは凍結記録）／`ADR-0014`（N03採用・SRID6668・5桁コード）／`ADR-0015`（マテリアライズ・`unit_kind`継ぎ目）／`ADR-0013`（PostGISコンテナ・生SQLマイグレ）／学習メモ `docs/notes/2026-06-25-n03-ingest.md`

## なぜ（背景・課題）
結合の的＝N03（行政区域シェープファイル）を PostGIS に入れる機構が未決（`docs/99` 保留）。実装フェーズ（ETL縦スライス）の入口。**取得→投入→正規化**の3工程で、誰が何をやるかを決める。

## 結論（決定）
**ハイブリッド**：
- **投入**（シェープ→PostGISテーブル化＝機械的な①〜⑤）は**外部ツール**に任せる。
- **正規化**（5桁コード化・年度固定・値域チェック＝本丸の結合基盤）は **SQL・Go** で自前に持つ（層1検証対象）。
- **投入ツール＝`shp2pgsql`**（シェープに必要十分。文字コード `-W CP932`、SRID `-s`（→6668）、空間索引 `-I`）。**⚠「PostGIS 同梱＝追加導入ゼロ」という当初前提は誤りと段0で判明＝下記「追記」。ローダの調達は `docs/99`「N03 投入経路の確定」で段1に再決定。**
  - **形式がシェープでなくなる／再投影が複雑な時のみ `ogr2ogr`（GDAL）へ寄せる**（多形式・PROJ再投影が強い）。可逆。
- **取得**＝境界は年1回・低頻度ゆえ**直リンクの取得スクリプト**（年度・都県をパラメータ）で半自動。完全自動化はしない。
- 投入ツールは serving（一体型）バイナリに入らない**データ投入時の道具**＝実行時の攻撃面とは別レイヤー（`net/http`/Biome の軸と矛盾しない）。

## 検討した代替案と捨てた理由
- **Goの `cmd/ingest` に全部（①〜⑤自前）** … 図形解析・SRID・索引を再実装＝**周辺を厚くしすぎ**（`CLAUDE.md`）。低頻度の境界投入に過剰。
- **投入も正規化も外部ツール任せ** … ドメイン正規化（本丸・層1検証対象）が手順書に埋もれる。

## 影響（結果・トレードオフ）
- お作法（取り決め）＝`backend-conventions` §5。**正規化ロジックは SQL/Go に持つ＝投入ツールを替えても不変**（継ぎ目・`ADR-0015`）。
- `shp2pgsql` が `postgis/postgis` イメージに含まれるかは**実装時に1コマンド確認**（`docker run --rm postgis/postgis which shp2pgsql`）。
- 文字コード（CP932が定番）・SRID は**実ファイルの `.prj`/`.dbf` で確認**（憶測しない）。
- GDAL 導入は寄せ先のときだけ（常時依存にしない）。

## 追記（2026-06-25・段0検証で前提修正）
- 段0 の実機確認で **`postgis/postgis:16-3.4` に `shp2pgsql`/`ogr2ogr` は非同梱**と判明（拡張＋SQLスクリプトのみ・ローダ binary は別パッケージ：`shp2pgsql`＝Debian `postgis`／`ogr2ogr`＝`gdal-bin`）。本ADRの「`shp2pgsql`＝PostGIS同梱＝ゼロ追加」前提は崩れた。
- **ハイブリッド（投入と正規化を分ける）判断そのものは有効**。変わるのは「ローダ binary をどう調達するか」だけ。
- 調達の選択（a: ローダを足したカスタム/別 ingest イメージ／b: 投入時だけ別 client イメージ／c: `ogr2ogr` へ寄せる）は **`docs/99`「N03 投入経路の確定」で段1着手時に決定**し、本ADR・`backend-conventions` §5 を更新する。
- **→ `ADR-0023` で確定（2026-06-25）**：置き場所＝使い捨ての別コンテナ（GDAL 公式イメージ `ghcr.io/osgeo/gdal`・案A）／ローダ＝`ogr2ogr`。b と c を合わせた形（別 client イメージ＝GDAL 公式、その中の `ogr2ogr` を使う）。a（DB イメージに同居）は攻撃面・再現性で却下。
- なぜ事前に分からなかったか＝「shp2pgsql は PostGIS に付属」という一般知識を、**特定の docker イメージで検証せず断定**したため（`docs/ai-feedback.md` F-001 の同型）。F-001 の「実装時に確認」但し書きが段0で機能し、段1で依存する前に捕捉できた。
