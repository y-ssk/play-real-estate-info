# ADR-0008: 相場分野の指標定義 — 公的地価を背骨に、取引は実勢としてカルテへ

- ステータス: 承認
- 日付: 2026-06-24
- 関連: `ADR-0005`（指標化の高度）/ `ADR-0006`（集計の共通形）/ `ADR-0007` / `docs/99`（バックログ優先1）/ `docs/01`§2§3 / `docs/02`§3§8 / `docs/api-if-spec/XPT002・XIT001・XPT001・XCT001`

## なぜ（背景・課題）

割れる分野の「相場（価格・地価）」を、手持ちの価格系4APIで何の数値で表すかを決める。相場は「時間軸（相場の推移・資産性）」という差別化の核（`docs/01`§2）に直結する。
価格データは性格が2つに分かれる：**公的地価（XPT002・XCT001）＝定点・継続・年次で、街の地価水準を全国そろえて比べられ推移に最適**／**実取引（XIT001・XPT001）＝市場実勢だがばらつき大・物件種別混在・座標は限定的**。

## 結論（決定）

1. **公的地価（XPT002）を相場の背骨にする**。
   - 色分け（市区町村を色で塗る）＝住宅地の地価の**単価の中央値・最新年**。
   - 重ね（実物を地図に置く）＝地価の調査地点（標準地/基準地）を単価の大小で点表示（**実位置**の点）。
   - カルテ（街を選ぶと出る詳細）＝同一地点の**年次の地価グラフ（推移＝時間軸の核）**＋変動率。

2. **実取引（XIT001）は「実勢」としてカルテに回す**。種別ごとの取引単価（総額÷面積）の中央値・件数・推移。**色分け・重ねには使わない**（種別混在・ばらつき大で街の代表値にすると誤読しやすい）。取引点 XPT001 は点が「最寄り駅の位置」で物件の実位置でないため、地図に重ねない。

3. **用途・物件種別は混ぜない**。住宅地を見出しにし、商業地や中古マンション等は別の数字として並べる（混ぜると重みづけ＝点数化に滑る。`ADR-0006` の浸水深と同じ考え方）。

4. **代表値は中央値**（平均は極端な高値1件でぶれる）。**色分けは中央値1本／カルテは複数の統計＋件数で「実態」と「確からしさ」を示す**：中央値（代表）＋ばらつきの幅＋件数（数値の確からしさ）＋必要なら平均（中央値との差で偏りが分かる）。幅は外れ値に強い範囲（四分位など）が無難。**具体の統計セットはカルテ設計（ブロック3）で確定**。

5. **鑑定評価書（XCT001）はMVP見送り**。最も詳細だが最新5年・標準地数も限定的で重い。将来カルテの深掘り用に温存。

## 検討した代替案と捨てた理由

- **色分けを取引価格の中央値にする** … 物件種別混在・ばらつき大・座標なしで街の代表値にすると誤読しやすい。公的地価は定点・継続で全国そろえて比較できるため背骨に。取引は実勢としてカルテへ。
- **代表値を平均にする** … 高値1件でぶれる。中央値を採用。
- **用途・種別を混ぜた単一価格** … 商業地等が混ざり誤導。重みづけ＝点数化に該当。混ぜない。
- **XPT001 取引点を物件位置として地図に重ねる** … 点が最寄り駅位置で物件実位置でない。誤解の元。使わない。
- **XCT001 をMVPで取り込む** … 重く・最新5年限定・地点少。MVPは XPT002 で地価は足りる。見送り。

## 影響（結果・トレードオフ）

- XPT002：年次・タイル取得（z/x/y＋year、1995-2024）、結果に `city_code`。当年は整形文字列・前年は生値で値形式が違う → 取り込みで正規化。用途区分コードの凡例はIF内にあり。
- XIT001：`city` で市区町村取得可・四半期（2005Q3-）。総額→単価へ変換（÷面積）、物件種別は自然言語、`DistrictCode` は継続性保証なし。中央値はレコード集計が必要。
- 推移（時間軸）はカルテの年次グラフで持つ＝相場が他分野と違う強み（`docs/01`§2）。
- 相場の集計も `ADR-0006` の共通形（単位ポリゴンへ空間結合）に乗る＝メッシュ移行に強い。
- カルテに載せる具体の統計セット（平均の要否・幅の取り方・分布グラフ）はブロック3で確定。
- 残ブロック：将来・教育の指標定義、カルテの中身、比較体験。
