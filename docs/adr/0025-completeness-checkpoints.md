# ADR-0025: 全量点検を二レンズ化し「枠の完全性」を点検する（ADR-0004の補遺）
- ステータス: 承認
- 日付: 2026-06-26
- 関連: `ADR-0004`（全量マップ・全量点検＝本ADRが拡張。`ADR-0004` のマップは凍結スナップショット）／**生きた手順＝`docs/04` §8**／**生きた全量マップ・運用ルール＝`docs/99`**／学習メモ `docs/notes/2026-06-26-completeness-checkpoints.md`

## なぜ（背景・課題）
段1（実装開始後）に「機能一覧・画面一覧・画面遷移・トップページ」が初めて必要と判明した。`ADR-0004` の「全量マップ＋節目点検」を敷いていたのに漏れた。根因＝全量マップの軸 E（フロント）が**技術・視覚の部品**（エンジン・状態管理・DS・レイアウトパターン）で構成され、**プロダクトのUX構造**（情報設計・画面・遷移・導線・トップページ）が項目として無く、節目点検で素通りした。仕組みが自発検知できず人が気づいた＝属人依存が残っていた（詳細＝学習メモ）。求めるのは「人力の気づき」でなく**構造としてのチェックポイント**。

## 結論（決定）
`ADR-0004` の「全量マップ＋節目点検」を凍結のまま、次の4点で拡張する：
1. **二レンズ点検**：節目（ブロック/フェーズの変わり目）で〈内→外＝データ/基盤〉と〈外→内＝ユーザー導線→画面→機能〉の**両レンズ**で全量マップに照らす。
2. **全量マップ E 分割**：E を **E1 フロント技術** と **E2 UX・情報設計**（機能一覧・画面一覧・画面遷移・導線・エントリ・画面別スコープ）に分ける。**生きた全量マップは `docs/99` に置く**（`ADR-0004` のはスナップショット）。
3. **枠の完全性メタ点検**：フェーズ移行で「別の役割（使う人/デザイナー/運用者/セキュリティ）なら、どの軸を足すか」を自問し、軸内でなく**枠そのもの**の漏れを問う。
4. **スライス着手前の小ゲート（DoR）**：各スライス入口で数問——`docs/05` に無い画面/遷移に触れるか・未決の契約/データを前提にしてないか・空/読込/エラー/出典を考えたか。

## 検討した代替案と捨てた理由
- **重厚WBSで前倒しに全量固定** … 硬直・オーバーエンジニア（`ADR-0004` で却下済の再確認）。我々はスクラム寄りゆえ「常設の点検＋精査」で安全を得る。
- **現状（単一レンズ＋節目点検）維持** … 枠の偏りを検知できず今回露呈 → 却下。
- **形式を増やして点検を厚くする** … 過剰プロセスは別の失敗。点検も薄く（数問の自問・数行照合）に留める。

## 影響（結果・トレードオフ）
- 生きた手順＝`docs/04` §8、生きた全量マップ（E1/E2）＝`docs/99`、`CLAUDE.md` から導線。
- 直後の適用：**両レンズで `docs/05`（UX・画面の柱）を起こす**。
- トレードオフ：点検の手数が少し増えるが、考慮漏れの手戻りの方が高くつく。点検は軽量を維持（儀式化しない）。
