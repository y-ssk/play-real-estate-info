# ADR-0012: 「面で比べる」体験 — 色分け地図＋絞り込み＋ピン留め＋並べ替え一覧表（比較ビューはv1）

- ステータス: 承認
- 日付: 2026-06-24
- 関連: `ADR-0005`（指標化の高度）/ `ADR-0011`（カルテの骨組み）/ `docs/99`（バックログ優先1）/ `docs/01`§3§5§6

## なぜ（背景・課題）

価値定義の最後＝「面で比べる」体験を確定する。比較は3フェーズで段階的（MVP探索 → v1横並び比較）。MVPで作る探索体験と、v1へ渡すデータ・骨組みの線引きを決める。

## 結論（決定）

1. **MVPの「面で比べる」＝色分け地図＋絞り込み＋ピン留め＋並べ替え一覧表**。
   - 色分け地図：分野ごとの単一指標を濃淡で塗り、地域全体を一目で比較（`ADR-0005`）。
   - **並べ替え一覧表**：街を行・指標を列にし、好きな指標で並べ替え（地価が安い順、人口が増える順…）。地図が苦手な「数字でじっくり読む人」に効く。単一指標での並べ替え＝点数化ではない。

2. **絞り込みは「市区町村ごとに持つ数値すべて」に効かせる**。色分けの代表値だけでなく、カルテの件数・有無（保育施設数、医療機関数、災害履歴件数、学区の有無など）も対象。各指標に条件（境目）を課し合致する街を残す方式で、**重みづけ＝スコアリングはしない**。持っていないデータ（学校の質等）では絞れない。

3. **ピン留めの永続化はMVPでブラウザ保存（localStorage）**。アカウント・サーバー不要で「再読み込みで消える」不便だけを安く解消し、認証スコープ（`docs/01`）には触れない。端末をまたぐ保存（アカウント＋サーバー）はv1。数個を見比べる前段として使う。

4. **横並び比較ビューはv1**。カルテの骨組み（`ADR-0011`）を再利用。形は横並びカルテか比較テーブル（指標×街）で、比較テーブル寄りを想定するが実物を見て決める。MVPはデータと骨組みを揃えるところまで。

## 検討した代替案と捨てた理由

- **地図だけ（一覧表なし）** … 数字で突き合わせたい人を取りこぼす。並べ替え一覧表を足す。
- **絞り込みを色分け指標だけに限る** … 件数・有無しか持たない分野（教育・生活施設等）が絞れない。全集計値に広げる。
- **ピン留めをセッション内のみ** … 再読み込みで消え不便。localStorage で安く永続化（認証不要）。
- **ピン留めをアカウント保存にする** … 認証はスコープ外（`docs/01`）。v1へ。
- **比較にレーダーチャート等** … 複数指標の正規化が要り、点数化に滑る。避ける。
