# ADR-0032: 面塗り指標の色相体系 — 慣例色を最優先、慣例なき量的指標は分野で色相を束ねる（各指標内は濃淡）

- ステータス: 承認
- 日付: 2026-07-05
- 関連: `ADR-0005`（色に良し悪しを込めない＝本ADRの前提）・`DESIGN`§1（データ色・更新先）・`mapTokens.ts`・`metrics.ts`・`docs/99`・洪水スライス（青の初適用）

## なぜ（背景・課題）

逐次配色が緑ランプ1本（`mapTokens.CHOROPLETH_FILL_RAMP`）を全ての量的指標（面積・地価・高齢化）で共有していた。面塗りはトグルで1指標ずつ表示するため、切り替えても「緑の濃淡」ばかりで、今どの指標を見ているかが凡例頼みになる（層4オーナー懸念「複数の指標があるのにみんな緑で何を比較しているか混乱しかねない」）。指標が増えるほど悪化する。かつ「洪水だけ青・他は緑のまま」の場当たりは無自覚な例外＝避ける。配色を体系として定める。

## 結論（決定）

面塗り指標の配色を次の優先順位の体系で定める。

1. **社会的慣例色が最優先**（誤認防止・`DESIGN`§1）：浸水(洪水/津波/高潮)=青／土砂=暖色(黄〜赤)／液状化=慣例が定まらず体系側で別途割当。
2. **慣例のない量的指標は分野で色相を束ねて識別**：相場=緑／将来=紫系（人口増減=発散 紫↔緑 PRGn・高齢化=紫 Purples 逐次）／基盤(面積)=灰。
3. **各指標の"中"は単色の濃淡＝量の大小のみ**（発散は符号付き指標のみ）。色に良し悪しを込めない（`ADR-0005`）。
4. **予約色を侵さない**：青=水害／コーラル=UI操作／スレート・near-black=境界/ホバー／白=絞り込みスクリム。
5. **色覚配慮**（ColorBrewer 単色/発散系）。**重ね系（点/線オーバーレイ）は別体系**（重ね機構の時に定義）＝面塗りと混ぜない。
6. **具体割り当ては層4目視で評価・確定**（暫定調整あり。特に将来=紫・面積=灰は実画面で見え方を評価する）。

実装は mapTokens に色相別の逐次ランプを持ち、metrics の各指標が色相を選ぶ（registry 参照）＝**コードが体系から外れられない構造**にする。

## 検討した代替案と捨てた理由

- **緑ランプ1本を全指標で共有（現状）** → 指標識別が困難・懸念の元＝捨てた。
- **指標ごとに全部別色相** → 色相が枯渇し無秩序＝捨てた。分野で束ね＋慣例優先にする。
- **災害分野を一律「青」で束ねる** → 土砂の暖色慣例（`DESIGN`§1「土砂=暖色（黄〜赤）」）と衝突＝捨てた。ハザードは種類ごとに社会的慣例色があるので、慣例を分野束ねより優先する。

## 影響（結果・トレードオフ）

- **正の更新**：`DESIGN`§1（割り当て表＋原則）・`docs/99`（確定索引＋実装スライス）。
- **実装の順序**：本スライス（#71）で既存4指標を体系色相へ（面積=灰・地価=緑・高齢化=紫・人口増減=発散 据置）→ 洪水スライスで青の初適用 → 土砂/液状化は将来スライスで慣例色。
- **無自覚な例外の排除**：緑独占を一括で解消。暫定（紫/灰）は層4評価で確定と明記＝自覚的な暫定。
- **影響なし**：`ADR-0005`（本ADRはその系＝各指標内は濃淡で大小・良し悪しを込めない）・データ/算出・カルテ。表現層のみ。
- **トレードオフ**：緑が相場と発散(人口増加側)で重なる／紫が将来の逐次と発散で重なるが、いずれもトグルで同時に出ないため実害は小（別画面）。層4で評価。
