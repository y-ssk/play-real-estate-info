# ADR-0009: 将来分野の指標定義 — 人口増減率を主軸（推計として扱う）、都市計画は中核2つを重ね

- ステータス: 承認
- 日付: 2026-06-24
- 関連: `ADR-0005`（指標化の高度）/ `ADR-0006`（集計の共通形）/ `docs/99`（バックログ優先1・保留「コード凡例収集」「出典/欠損UI」）/ `docs/01`§2§3 / `docs/02`§3§8 / `docs/api-if-spec/XKT013・XKT031・XKT001・XKT002`（ほか XKT003/014/023/024/030）

## なぜ（背景・課題）

割れる分野の「将来（人口・都市計画）」を、手持ちデータで何の数値で表すかを決める。「面・将来」という芯（`docs/01`§2）の片翼。
将来推計人口（XKT013）は250mメッシュで2020→2070年（5年刻み）の推計値・高齢化率等を持ち、`SHICODE` で市区町村集計できる。都市計画は区域区分・用途地域ほか多数のポリゴンがある。

## 結論（決定）

1. **主軸＝将来推計人口（XKT013）**。
   - 色分け（市区町村を濃淡で塗る）＝**人口の増減率（2020→2050）**。切替で**高齢化率（2050）**も（将来の別の顔）。
   - カルテ＝人口の**推移グラフ（2020〜2070）**＋高齢化率の推移＋生産年齢人口など。
   - 重ね＝人口メッシュ（v1のメッシュ表示につながる。MVPは市区町村集計が主役）。

2. **将来推計人口は「推計（予測）」として扱う**。地価実績や災害区域（指定された事実）とは性質が違うため、**出典・前提を明示し、断定的に見せない**。小人口メッシュの「秘匿」（`HITOKU`/`GASSAN`）は「データなし」と区別する。＝出典/欠損UI（保留・優先度高）と連動する横断原則。

3. **人口集中地区 DID（XKT031）**：カルテ＝市街地度（DID人口割合・面積割合）＋前回比（集約が進む/緩む）。重ね＝DIDの範囲。色分けの主軸にはしない。

4. **都市計画は中核2つを重ねる**：**用途地域（XKT002）・区域区分（XKT001）**を種類ごとに色分けして地図に重ね（街の性格・骨格が見える）、カルテに市街化区域の面積率・用途構成。これらは「数値の濃淡」でなく「区分（カテゴリ）」の色。

5. **専門5種はMVP見送り**：立地適正化（XKT003）・防火/準防火（XKT014）・地区計画（XKT023）・高度利用（XKT024）・都市計画道路（XKT030）。住む人への効きが弱い／局所的で、表示にはコード凡例の収集も要る。重ねレイヤーは後付けが安いため必要時に足す。

## 検討した代替案と捨てた理由

- **人口を絶対数で色分け** … 大都市が常に濃いだけで「将来トレンド」を表さない。増減率を採用。
- **推計を実績と同列に断定表示** … 予測を事実のように見せると誤導。推計と明示し前提・出典を添える。
- **都市計画の専門5種をMVPに入れる** … 効きが弱く局所的、凡例収集コストもある。後付けが安いので見送り。
- **DIDの市街地度を色分け主軸にする** … 現状の市街地度は「将来」の主軸より弱い。カルテの素性指標に留める。

## 影響（結果・トレードオフ）

- XKT013に増減率フィールドは無い → 2年次（例 2020/2050）の差分から算出。秘匿処理で小人口メッシュは値欠落 → 集計時に欠測として扱い「データなし」と区別（層1）。タイル取得（z/x/y）、`SHICODE` で市区町村集計。
- 都市計画系（区域区分・用途地域含む）のコード凡例は原典リンク依存 → 凡例収集（保留事項・全レイヤー）が用途地域・区域区分でも必要。日付表記の和暦/西暦混在は取り込みで正規化。
- 将来の集計も `ADR-0006` の共通形（単位ポリゴンへ空間結合）に乗る＝メッシュ移行に強い。
- 「推計の明示・秘匿とデータなしの区別」は出典/欠損UIの設計に引き継ぐ。
- 残ブロック：教育の指標定義、カルテの中身、比較体験。
