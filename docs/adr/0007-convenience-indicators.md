# ADR-0007: 利便分野の指標定義 — 点/線データは件数を基礎に、交通のみ色分け（両用）

- ステータス: 承認
- 日付: 2026-06-24
- 関連: `ADR-0005`（指標化の高度）/ `ADR-0006`（災害・集計の共通形）/ `docs/99`（バックログ優先1）/ `docs/01`§3 / `docs/02`§3§8 / `docs/api-if-spec/XKT015`（駅別乗降客数）ほか XKT010/017/018/011/019

## なぜ（背景・課題）

共通土台のもう一方「利便」を、手持ちのMLITデータで何の数値で表すかを決める。
災害はポリゴンだったので面積率で統一できたが、利便のデータ（駅・施設）は**点や線**で、面積率が使えない。点を市区町村でまとめる方法を選ぶ必要がある。

> 表示の3モードの語は `docs/glossary.md`「表示の3モード」に固定（①市区町村を色分け＝面塗り、②実物を地図に重ねる＝塗り絵、③街を選ぶと出る詳細パネル＝カルテ）。

## 結論（決定）

1. **点/線データの集計方針**：**素の件数を基礎事実として必ず保持**する。街どうしを比べる正規化が要るときは **密度（件数÷面積）** を採る。
   - 人口あたり（÷人口）は人口データ依存が増えるため見送り。
   - アクセス（最寄りまでの距離）は本質的に点/メッシュ向きで、市区町村粒度では扱いにくくメッシュ移行時に作り直しになるため見送り。
   - いずれも事実ベースで、複数を混ぜた点数化はしない（`ADR-0005`）。

2. **分野の割り当て**：
   - **利便＝交通（駅 XKT015）＋生活施設（医療 XKT010・図書館 XKT017・役場 XKT018〔・福祉 XKT011・自然公園 XKT019〕）**
   - 教育（学校 XKT006・保育 XKT007・学区 XKT004/005）は別分野（次ブロック）。

3. **振り分け**：
   - **交通（駅 XKT015）＝両用**。①色分け＝市区町村内の**合計乗降客数（直近の正常年・2023を基本）**。②重ね＝駅を乗降客数の大小で点表示。
   - **生活施設（医療・図書館・役場〔福祉・自然公園〕）＝②重ね（点）＋③カルテに種別ごとの件数**（種別は混ぜない）。**色分け（①）はしない**。密度による色分け・比較が要れば将来／比較ビュー段階で。

## 検討した代替案と捨てた理由

- **件数で色分け** … 面積の広い市ほど多く出て密度の薄さが見えない。件数は基礎事実として保持しつつ、色分けの正規化には密度を採る。
- **人口あたり／アクセスを採用** … 利便の意味には近いが、人口データ依存・点/メッシュ向きで市区町村MVPに重い。メッシュ段階向きとして見送り。
- **生活施設も色分け** … 種別ごとに色分け面を増やすと過剰、種別を混ぜた合計件数は無意味。MVPは重ね＋カルテ件数に絞る。
- **交通の代表値を駅数にする** … 駅数では鉄道結節の強さ（賑わい）を表せない。乗降客数を採用。「大ターミナル1つで数値が大きく出る」限界は、駅点の分布（②重ね）で補って見せる。

## 影響（結果・トレードオフ）

- XKT015は乗降客数の時系列（2011〜2023, 整数）を横持ちで返す → 駅×年の縦持ちに変換。各年の「データ有無コード」で欠測判定（層1）。2020はコロナで凹むため単年異常値に注意（直近の正常年か短期平均、実装時に確定）。
- XKT015の駅は駅区間の **LineString** → 市区町村への割付は線の所在で判定（空間結合は優先2）。生活施設は点 → 含む市区町村で数える。
- 利便の集計も `ADR-0006` の共通形（単位ポリゴンへ空間結合して集計）に乗る＝市区町村↔メッシュの単位差し替えに強い。
- 残ブロック：相場・将来・教育の指標定義、カルテの中身、比較体験。
