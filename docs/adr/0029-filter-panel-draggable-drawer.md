# ADR-0029: 絞り込みパネルは可動ドロワー（左端から開閉＋ヘッダ掴みで移動）。カルテは右側固定のまま

- ステータス: 承認
- 日付: 2026-06-28
- 関連: `DESIGN`§2（地図UIパターン＝更新元）・`docs/05`§3（S1内 絞り込みパネル）・`ADR-0028`（④再定義＝絞り込みは地図ハイライトに徹する）・`ADR-0018`（パネル開閉＝状態）・`docs/99`「実装スライス」④/新スライス

## なぜ（背景・課題）

`DESIGN`§2 の「③開閉式パネル」は **閉=地図全面／開=固定領域** までしか定めておらず、開いたパネルの **置き場と可動性** は決めていなかった。④（Issue #57・PR #58 で dev 反映）の絞り込みパネルは現状この「固定領域」として実装されているが、層4目視でオーナーから「**絞り込み中も地図を広く使いたい。端から出し入れでき、かつ掴んで動かせる形にしたい**」との要望が出た。

固定領域だと、絞り込み操作中は常に地図が削られる。`ADR-0028` で絞り込みは「地図ハイライトに徹し→クリックでカルテ」へ再定義した＝**絞り込み中こそ地図が主役**になったため、パネルが地図を占有し続けるのは導線と噛み合わない。出し入れ（開閉）＋移動でユーザーが構えを調整できるようにする。

## 結論（決定）

絞り込みパネル（F3）を **可動ドロワー** にする。`DESIGN`§2「③開閉式パネル」の「開いた状態」の置き方を、パネルの役割ごとに次の2系統へ具体化する。

- **絞り込みパネル（F3）＝左端ドロワー＋移動可能**
  - **左端**に格納し、ハンドル/ボタンで開閉。開くと左端からスライドして出る（閉じれば地図が全面に戻る）。カルテ（右端固定）と辺を分け、取り合わない。
  - 開いた後、**ヘッダ（つかみ手）をドラッグするとパネルを浮かせて任意位置へ移動できる**。
  - **本体（中身）のドラッグは地図のパン操作へ通す**＝パネルが地図操作を奪わない。移動はヘッダでのみ起こす（地図ドラッグとの食い合いを構造的に断つ）。
- **カルテパネル（F5）＝右側固定のまま**（`DESIGN`§2・実装済）。可動化しない（読み込む収束フェーズの安定した置き場を保つ）。

開閉・移動は **“状態”であって画面遷移ではない**（`ADR-0018`・`docs/05`§4 遷移図は不変）。状態の真実は store（位置・開閉）に持ち、`DESIGN`§2 のモーション用途トークン（`--motion-base 200ms`・`prefers-reduced-motion`）に従う。モバイルは従来どおりボトムシート（PC実装後・`DESIGN`§2）＝可動ドロワーはPCの構え。

## 検討した代替案と捨てた理由

- **案A：固定領域のまま（現状維持）** → 捨てた。絞り込み中も地図が削られ、`ADR-0028`「絞り込み＝地図ハイライト主役」と噛み合わない。オーナー要望に応えない。
- **案B：左端ドロワー（開閉のみ・移動なし）** → 「まず開閉だけ」の刻み案として提示したが、オーナーは**両取り（ドロワー＋移動）を一気に**選択。移動可能まで本スライスで入れる。
- **案C：フローティングパネルのみ（端ドロワーにせず最初から浮く小窓）** → 捨てた。既定の収まり位置（端）が無いと初見で居場所が定まらず、地図を全面に戻す「閉じる」体験が弱い。端を定位置に持つドロワーを基本に、移動は副次能力とする。
- **案D：カルテも可動化して統一** → 捨てた。カルテは「読み込む」収束フェーズの安定が要る（`DESIGN`§2）。可動は「広く探す」段の絞り込みにこそ効く。役割で置き方を分ける（左=探索の可動ドロワー／右=収束の固定）。

## 影響（結果・トレードオフ）

- **得るもの**：絞り込み中に地図を広く使える。出し入れ＋移動でユーザーが構えを調整。左=探索（可動）／右=収束（固定）の左右対比が導線（`docs/01`§3「広く探す→ピン→比較」）と一致。
- **トレードオフ（過剰性の自覚）**：可動ドロワーは**周辺UI部品としては作り込みが重い**（本丸＝地図表現/データに対し周辺・`CLAUDE.md`）。ドラッグ実装（ポインタ捕捉・地図イベントとの分離・画面外へ出さないクランプ・`prefers-reduced-motion`）の手当てが要る。オーナーがMVPでの採用を明示判断した上での選択。
- **正の更新**：`DESIGN`§2（パネルの置き方を「固定領域」→「役割別＝左可動ドロワー/右固定」へ具体化）・`docs/05`§3（S1内 絞り込みパネルに可動ドロワー注記）。`ADR-0028`（絞り込みの導線）は不変＝本ADRは「絞り込みパネルの構え（開閉・置き場・可動）」だけを足す。
- **影響なし**：`ADR-0028`（絞り込み=ハイライト→カルテ）・`ADR-0011`（カルテ中身）・`ADR-0018`（状態=Zustand。位置/開閉も状態として持つ＝同方針）・④の純ロジック（`filtering.ts`）。ドロワーは絞り込みUIの“器”であって中身のロジックは不変。
- **共通部品**：可動ドロワーは将来カルテ以外でも使える余地があるが、現状の消費先は絞り込みのみ＝**先回りで汎用化せず**、絞り込みが消費する形で部品化する（3.5/`ADR-0027` の「消費先が見えてから部品化」方針と同じ）。
- **規約例外（フォーカストラップを入れない）**：melta `prohibited.md:70` はモーダル Drawer 前提のフォーカストラップ（tab を内部に閉じ込める）を要求するが、本パネルは**非モーダル小窓**（背面の地図を操作させる＝本体ドラッグを地図パンへ通すのが核）ゆえトラップを入れない＝トラップは「背面を触らせる」非モーダル設計と矛盾する。代わりに非モーダルとして相応の a11y を備える＝**ESC で閉じる／閉じたらフォーカスを起点のトグルへ戻す**（`no-unjustified-convention-exceptions`＝例外は根拠なく残さない）。
- **スライス**：④の機能の核（#57/PR #58）とは分けた**フォロー増分（別スライス・別Issue・別PR）**＝レビュー単位を濁さない（3.5/3.6 を分けたのと同型）。
