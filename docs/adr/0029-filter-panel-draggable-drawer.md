# ADR-0029: 絞り込みパネルは左の操作列のボタンで開閉する左オーバーレイのドロワー（PC固定・移動なし）。モバイルは別スライス。カルテは右側固定

- ステータス: 承認
- 日付: 2026-06-29
- 関連: `DESIGN`§2（地図UIパターン＝更新元）・`docs/05`§3（S1内 絞り込みパネル）・`ADR-0028`（④再定義＝絞り込みは地図ハイライトに徹する）・`ADR-0018`（パネル開閉＝状態）・`docs/99`「実装スライス」④/#59

## なぜ（背景・課題）

`DESIGN`§2 の「③開閉式パネル」は **閉=地図全面／開=固定領域** までで、開いたパネルの置き場・可動性・他オーバーレイとの衝突を決めていなかった。④（#57・PR #58 で dev 反映）の絞り込みパネルは現状「固定領域」で、層4でオーナーから「絞り込み中も地図を広く使いたい・端から出し入れしたい」要望が出た。

ここで2度、層4で破綻した：
1. **可動ドロワー（端から開閉＋ヘッダ掴み/本体ドラッグで移動）**（2026-06-28・PR #60 初版）＝トグルとパネルの重なりで開閉ボタンが2つに見える・飾りアイコンが非ボタン・移動アニメ常時でドラッグがゴム化・任意移動が「真ん中に来て邪魔」。
2. **左上の角に丸アイコン1つを別レイヤーで浮かせて開閉**（簡素化版）＝丸アイコンが**モーダルと別に重なって違和感**。さらに左上の角は既に **倍率の数値表示（`top8/left8`）と指標トグル（`top40/left8`）** で埋まっており、絞り込みトグルがそれらと**衝突**した。

＝置き場と「トグルとパネルの一体感」を決めずに作ったのが原因。本 ADR で配置・開閉の構え・PC/モバイルの分担を確定する。

## 結論（決定）

絞り込みパネル（F3）は **左の操作列のボタンで開閉する、左から出るオーバーレイのドロワー**。PC では動かさない。

- **トグル＝左の操作列のラベル付きボタン1つ**（`SlidersHorizontal`＋「絞り込み」）。**指標トグルの下**に置き、**倍率表示・指標トグルと衝突しない**位置にする（左上の角の取り合いを避ける）。別レイヤーで浮かせる丸アイコンは**廃止**（モーダルと重なる違和感の元）。
  - **閉**：そのボタンだけが見える（押すと開く）。
  - **開**：左からスライドして出るオーバーレイのパネル（従来のサイズ感）。**開いている間はトグルボタンを隠す**＝ボタンとパネルが重ならない（一体に見える＝閉↔開で同じ場所が姿を変える）。パネルのヘッダ＝タイトル「条件で絞り込む」＋**閉じる(X)**。
- **閉じる手段＝X と ESC**（本体・スライダーを触っても閉じない）。閉じたらフォーカスを起点のトグルへ戻す。
- **PC ではパネルを移動しない（固定）**。アニメは**開閉のスライドだけ**。
- **左＝探す（左オーバーレイ）／右＝収束（カルテ右固定）** の左右対称（`ADR-0028`「広く探す→ピン→比較」の探す段）。
- **モバイル（スマホ幅）＝ボトムシート**（全幅・下から引き上げ・`DESIGN`§2 のモバイル方針）で PC と挙動を分ける。**実装は別スライス（モバイル対応）に回す**＝当面 PC のみ整える（周辺UIに過剰投資しない・`CLAUDE.md`）。

開閉は **“状態”であって画面遷移ではない**（`ADR-0018`・`docs/05`§4 遷移図は不変）。状態の真実は store（開閉）。モーション用途トークン（`--motion-base 200ms`・`prefers-reduced-motion`）に従う。

## 検討した代替案と捨てた理由

- **可動ドロワー（ヘッダ掴み/本体ドラッグで任意位置へ移動）** → 採って層4で破綻＝捨てた。見た目と挙動が一致せず、任意移動はむしろ邪魔。**周辺UIに対し作り込みが過剰**で、得たい価値（地図を広く使う）は固定の開閉で足りる。
- **左上の角に丸アイコンを別レイヤーで浮かせて開閉** → 捨てた。モーダルと別に重なり違和感・倍率表示/指標トグルと衝突。トグルは操作列のボタンに統合し、開いている間は隠す（重ならない）。
- **カルテも可動化して統一** → 捨てた。カルテは収束フェーズの安定が要る。役割で分ける（左探す／右収束）。

## 影響（結果・トレードオフ）

- **得るもの**：他オーバーレイ（倍率・指標トグル）と衝突しない配置。**トグルとパネルが重ならず**「どれを押すと何が起きるか」が一意＝見た目と挙動が一致（層4指摘の解消）。実装が軽い（移動・座標 store・クランプ・移動アニメは不要）。
- **トレードオフ**：PC で位置を動かせない（オーナー判断＝移動は邪魔）。モバイルのボトムシートは別スライスへ（当面 PC のみ）。
- **正の更新**：`DESIGN`§2／`docs/05`§3／`docs/99`（確定索引＋スライス4d）。
- **撤回（実装から外す）**：可動ドロワーのドラッグ一式（pointer 捕捉・浮かせ量 `offset`・`clampDrawerOffset`・移動アニメ）・別浮きの丸アイコン・飾りの重複アイコン。
- **影響なし**：`ADR-0028`（絞り込み=ハイライト→カルテ）・`ADR-0011`（カルテ）・④純ロジック（`filtering.ts`）。器だけの変更。
- **規約例外（フォーカストラップ非導入）は維持**：本パネルは非モーダル（背面の地図を操作させる）ゆえモーダル前提のフォーカストラップは入れない＝矛盾する。代わりに ESC で閉じ・閉じたら起点のトグルへフォーカス復帰（`no-unjustified-convention-exceptions`・melta `prohibited.md:70`）。
- **併せて直す別件の不具合**：`ChoroplethLayer` の `removeFeatureState`/`setFeatureState` は source 未生成時に MapLibre が例外を投げる（`The source 'choropleth' does not exist`）。**source の存在確認ガード**を入れて直す（本 ADR の決定ではなく、同 PR で巻き取るバグ修正）。
- **既知の積み残し（別スライス 4c へ）**：PR #60 時点では、開いた**絞り込みパネル**が左オーバーレイで左上原点に出るため**指標トグル（面積/増減率）・倍率表示を覆う**（層4オーナー指摘）。要望＝**開いたパネルは指標トグル群を覆わない**（閉じている時の絞り込みボタン自体との重なりは可）。配置是正はバックログ（`docs/99` 4c・優先そこそこ高め）へ切り出し、PR #60 はオーナー判断でこの積み残しを承知の上マージする。
- **スライス**：④機能の核（#57/PR #58）とは分けたフォロー増分（#59・PR #60）。パネル配置是正（4c）・モバイル対応（4m）は**新スライス（別Issue）**として `docs/99` に積む。
