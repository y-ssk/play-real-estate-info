# ADR-0027: FE スタイル土台＝CSS変数の3層トークン／差し色コーラルを hex 確定
- ステータス: 承認
- 日付: 2026-06-27
- 関連: `ADR-0013`（FE器・「スタイル土台＝Tailwind＋melta-ui」と記録したが Tailwind は未導入＝本ADRで実態に合わせ更新）／`DESIGN`§1（差し色コーラル「仮確定」を本ADRで決着）§4（意味/用途トークン参照）§5（ダーク後付け）／`docs/02`§7（スタイル土台）／`docs/99` 保留「melta-ui トークン層の材料化」／実装スライス 3.5

## なぜ（背景・課題）
スライス 3.5（共通部品層の実体化＝DESIGN を実装に落とす）に着手するにあたり、現状を点検して2つの未決が判明した。
- **記録と実態の乖離**：`ADR-0013`／`docs/02`§7 は「スタイル土台＝Tailwind＋melta-ui」と記録するが、`web/` に Tailwind/PostCSS は未導入。現実のスタイルは各部品の JSX に hex を直書きするインライン方式（例 `KartePanel.tsx` の `#ffffff`／`#f1f5f9`、`MetricToggle.tsx` の `#334155`）で、同じ値が各所に散っている。`DESIGN`§4「生値でなく意味/用途トークンを参照」が未充足。
- **差し色コーラルの hex が一度も記録されていない**：`DESIGN`§1 は「ベース＝スレート／差し色＝コーラル（仮確定）」とするが具体 hex は未確定で、各部品は「hex 未確定ゆえ差し色を使わない」とコメントで保留していた。

melta-ui の `tokens/tokens.json` は中身が `../design/contracts/tokens.json` の一文だけの dangling 参照で、トークンの単一情報源として使えない（`docs/99` 既知）。土台を決めずに共通部品を作ると、インライン直書きの散在を量産してしまう。

## 結論（決定）
1. **FE スタイル土台＝CSS変数（カスタムプロパティ）の3層トークン**。`ADR-0013`／`docs/02`§7 の「Tailwind」部分を実態に合わせ更新する（Tailwind は採らない）。
   - **生値層**（パレット）：`--slate-900` … `--coral-600` 等。
   - **意味層**：`--color-text: var(--slate-900)` / `--color-accent: var(--coral-600)` など役割で命名。
   - **用途層**：共通部品は色名を書かず `var(--color-accent)` 等の用途トークンだけ参照（`DESIGN`§4）。
   - **ダークは後付け**：`body.dark { --color-text: …; … }` の1ブロックで意味層の中身を差し替え、cascade で全子孫へ届く。部品コードは不変（`DESIGN`§5「後付けできる構造を保つ」を構造的に満たす）。MVP はライトのみ実装。
   - **地図（MapLibre）は別経路**：MapLibre は CSS 変数を解さないため、地図 paint 値は従来どおり `web/src/styles/mapTokens.ts` が担う。これはどの土台案でも同じ。将来 CSS 変数を単一情報源に寄せ、`mapTokens.ts` の手写しを解消する（`docs/99` 宿題への地ならし）。
2. **差し色コーラルを hex 確定（候補B クラシック・brand/action の2段スケール）**。`DESIGN`§1「仮確定」を決着。
   - `--coral-600 = #D6443A`（**action**＝白文字が乗る面＝ボタン・選択中チップ。白文字コントラスト ≈ 4.5:1 で WCAG AA 適合）。
   - `--coral-500 = #F2615A`（**brand**＝文字を載せない強調＝選択リング・フォーカス・地図ピン）。
   - 差し色は「点」で使う（`DESIGN`§1・3-Color Rule）。青（浸水想定の慣例色）と衝突させない方針は不変。

## 検討した代替案と捨てた理由
- **TS トークンモジュール（`styles/tokens.ts` を import して inline style へ）** … 現行インライン方式に最も近いが、cascade が無いためダーク切替時に「dark の値を全部品へ配り直す配線（context 等）」を自前で書く必要があり、`DESIGN`§5 の後付け要件に重い → 採らない（移行コストの一度きりの差は後で逆転）。
- **Tailwind を導入（`ADR-0013` の当初記録に忠実）** … `dark:` 接頭辞でダークは効くが、PostCSS 等のビルド依存・攻撃面が増え、`ADR-0013`/`ADR-0021` の「依存・攻撃面を最小に」と逆行 → 捨てる。
- **コーラルを単一 hex で持つ** … 鮮やかなコーラルは白文字で AA を落とし、AA を満たす濃さは差し色の鮮やかさを損なう。2段スケール（brand=鮮やか/非テキスト・action=濃い/テキスト）で両立 → 単一値は捨てる。
- **暖色（オレンジ寄り）／ロゼ（ピンク寄り）のコーラル** … 暖色は土砂災害のデータ色（黄〜赤）と地図上で競合しやすい。クラシック（候補B）が語感・AA・データ色との分離のバランスで最良 → B を採用。

## 影響（結果・トレードオフ）
- `web/src/styles/` に CSS 変数のトークン層を新設（`global.css` の `:root`）。共通部品（`web/src/components`）は用途トークンを参照して実装する（スライス 3.5）。
- 既存のインライン直書き（`KartePanel`・`MetricToggle` 等）は、共通部品への置き換え／トークン参照へ順次移行（本スライスで着手・全置換は段階的でよい）。
- `mapTokens.ts` は当面そのまま（地図は別経路）。CSS 変数への寄せは `docs/99`「melta-ui トークン層の材料化」の宿題として継続。
- ダークモードは MVP 見送りのまま。ただし意味層を介すことで後付け1箇所で効く構造を確保。
- アイコンは `DESIGN`§6 のとおり Lucide を導入（SVG・必要時のみ・絵文字禁止）。
