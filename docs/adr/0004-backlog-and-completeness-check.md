# ADR-0004: 台帳をバックログ化し「全量点検」を仕組みにする

- ステータス: 承認
- 日付: 2026-06-23
- 関連: `99_decision-register.md`（本台帳＝バックログ） / `ADR-0003`（ブランチ・merge運用） / 発端のやりとり（本ADRの「なぜ」に経緯を保存）
- 反映PR: #11（feature/backlog-restructure → dev）

## なぜ（背景・課題）
P1（IF定義収集）完了後、「フロントエンドの基本方針（地図エンジン・フロント器・受け渡し仕様）」がロードマップの最後（P5）に置かれていたことにオーナーが違和感を示した（「APIを全部作ってからフロントは何から始める？は遅すぎる」）。これを発端に、**段取りの網羅性・優先度に漏れがあるのではないか**という問題提起があった。

掘り下げると、これまでの台帳運用は **「論点が出たら預ける＝漏れを後から拾う」** 方式（accretion）であり、**最初に全量を上から分解して検証する手順が無かった**。＝個々は良くても「全量が出ているか」は誰も保証していなかった。

そこで MVP を世に出すまでに要る作業を上から分解（全量マップ）し、既存ロードマップと照合した。結果、**実際に漏れ・希薄が7件**見つかった：

1. **価値定義（最大の漏れ）**：指標化（街の素性をどう数値化し束ねるか）・カルテ（エリアを選ぶと出る情報のまとまり）の中身・「面で比べる」体験。プロダクトの核なのに独立タスクが無く P2スライス要件と P5 UI に分散していた。
2. フロント基本方針の前倒し（地図エンジン MapLibre／器 React／受け渡し仕様）＝発端。データ層に結合するため P5 は遅い。
3. ローカル開発環境・DB基盤（PostGISの立て方・migration運用）＝P3着手の前提なのに棚に無い。
4. デプロイ/ホスティング先＝台帳に無し。
5. 共通結合・空間結合基盤（市区町村コード正規化・点/メッシュ→市区町村の割当・CRS正規化）＝埋もれ気味。
6. 認証・ユーザー機能の要否＝MVPスコープの確認事項。
7. パフォーマンス/データ量（首都圏全域の規模感・タイル枚数）＝希薄。

### 全量マップ（上から点検する際の照合枠）
- A 足場・環境（構成・ローカル環境・migration・秘匿・ブランチ・CI）
- B データ取得・変換（取得クライアント・ETL要件・IF定義・データモデリング・コード凡例・共通結合）
- C 指標化・体験（指標定義・カルテ中身・比較体験）← 価値の核
- D 配信・API（API設計方針・アクセス方式・タイル配信・データAPI）
- E フロント・地図（器・地図エンジン・受け渡し仕様・ベースマップ・状態管理・DS・UIレイアウト・出典/欠損UI）
- F 非機能（テスト・ロギング・エラー/欠損UI・パフォーマンス）
- G 公開・運用・法務（デプロイ先・MLIT規約・出典義務・名称・認証要否）
- H 進め方・運用（全量点検・PR/merge運用・セッション再開・用語辞書）

## 結論（決定）
1. **バックログ＝本台帳（`docs/99`）**。台帳を「確定索引＋保留リスト」から、**テーマ別・優先順・状態・依存を持つバックログ**へ格上げする（確定索引は維持）。全量タスクは必ずいずれかのテーマに割り付ける。
2. **優先順を価値定義先頭に再編**（オーナー並べ替え＋AI補正）。重い設計（価値定義→共通結合基盤）に集中し、**軽い確認（認証要否・地図エンジン/器の確認・環境ツール・一体型/構成の追認）は順番に縛らず前倒しで一括処理**する。詳細順は `docs/99` バックログ表。
3. **運用ルールに「全量点検」を追加**。節目（ブロックの変わり目・フェーズ移行）で上記「全量マップ」に照らし、**漏れを後から拾うだけでなく上から出し切る**。
4. 追加・変更は **MVP を出してスクラム的に改良する中で経験から出てくるもの**として扱い、**思いつきの継ぎ接ぎを禁ずる**（テーマ・優先・なぜを必ず持たせる）。

## 検討した代替案と捨てた理由
- 現状維持（accretionのみ）… 漏れを後から拾えるが全量を保証できない（今回まさに露呈）→ 却下。
- 重厚な WBS で全量を一度に固定 … 初期に固め過ぎ・オーバーエンジニア。バックログは「生きた台帳」として更新し続けるべき → 却下。
- フロント基本方針を従来どおり実装着手時（P5）に決める … データ層に結合し手戻りリスク。安い確認だけでも前倒しすべき → 却下（軽い確認バッチへ）。

## 影響（結果・トレードオフ）
- 以降の設計は **価値定義（指標化・カルテ・比較体験）から**入る。データモデリングと地図表現の両方の上流を先に固める。
- `docs/99` がバックログとして機能。節目の全量点検が習慣化（H領域に常設）。
- トレードオフ：全量点検の手間が増えるが、手戻り・考慮漏れの方が高くつくため許容。
- 本決定の経緯（やりとり）は本ADRに保存。バックログから本ADRへ参照導線を張る。
