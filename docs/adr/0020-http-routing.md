# ADR-0020: HTTPルーティング＝標準 net/http（Go 1.22+ ServeMux）。chi は可逆な差し込み先
- ステータス: 承認
- 日付: 2026-06-25
- 関連: `docs/99_decision-register.md`（保留→確定「HTTPルーティング機構/ライブラリ選定」・足場づくり）／**お作法の最新は `docs/backend-conventions.md` §4**（本ADRは凍結記録・取り決めの引き先ではない）／`docs/02_architecture.md` §6（ディレクトリ・`internal/handler/`）／`ADR-0016`（エンドポイントの形・タイル `{z}/{x}/{y}`）／`ADR-0013`（一体型1プロセス・攻撃面最小の軸・可逆な決定）／学習メモ `docs/notes/2026-06-25-http-routing.md`

## なぜ（背景・課題）
足場づくりの点検で、エンドポイントの形（`ADR-0016`）とハンドラ責務（`backend-conventions` §1）は確定済みだが、来た要求を振り分ける**ルータの機構/ライブラリ選定だけが未登録（預け漏れ）**と判明した。一体型Goサーバが捌くのは、値/形/カルテのAPI数本＋タイル（**パス引数** `/{z}/{x}/{y}`）＋ embed した FE の静的配信。何でルーティングするかを決める必要がある。

## 結論（決定）
**標準 `net/http` の `ServeMux` で組む（外部ルータを入れない）。**
- **Go 1.22+ の `ServeMux` はメソッド＋パスワイルドカード**（`GET /api/tiles/{z}/{x}/{y}`）を公式サポートし、`r.PathValue("z")` で取り出せる。歴史的にライブラリを要した「パス引数」の理由が消えた。
- **依存ゼロ＝一体型・攻撃面最小**（`ADR-0013` と同じ軸：FE lint を Biome 単一に・Vite 系から距離）。自分が書いていないコードをサーバ内で動かさない。
- **Go 1.22 以上を前提**とし、`go.mod` の `go` ディレクティブで固定（足場で go.mod 作成時）。
- **可逆**：将来ルートが増えてミドルウェア/グループ化が手書きで苦しくなったら、`chi`（標準 `http.Handler` 互換）を差し込む。今は入れない（YAGNI）。

## 検討した代替案と捨てた理由
- **`chi`（軽量ルータ）** … 標準で足りる今、依存・攻撃面・保守対象を先回りで増やす。標準互換ゆえ必要時に足せる（可逆）→ いま採る理由がない。
- **`gin` / `echo`（フレームワーク）** … 独自 `Context` 型でコード全体が枠組みの作法に染まり、標準 `http.Handler` から外れる。欲しいのはルーティングだけのMVPには過剰で、後の乗換費用も高い。捨てる。

## 影響（結果・トレードオフ）
- 取り決め（お作法）＝`backend-conventions` §4（ルータ＝標準 `ServeMux`／ルート登録は `cmd/api`／ハンドラは薄く store を呼ぶ §1.4）。
- **Go 1.22+ 縛り**が入る（`go.mod` で担保）。
- グループ化/ミドルウェアは素の `func(http.Handler) http.Handler` 合成を手書き（MVPの数本では軽微）。苦しくなったら `chi` へ（可逆）。
