# ADR-0030: データ拡張は2軸（指標＝コードのスライス／エリア＝データ操作の波）で足し算に保つ。エリアは段階拡張

- ステータス: 承認
- 日付: 2026-07-03
- 関連: 確定索引「対応エリア」・`docs/01`§4・`docs/02`§5§8・`ADR-0014`（pref/5桁コード）・`ADR-0015`（空間結合）・`ADR-0024`（N03投入運用）・`docs/99`「実装スライス」

## なぜ（背景・課題）

データ拡張には2軸ある＝**指標**（area_km2／人口増減／地価／災害…）と**エリア**（東京→首都圏→全国）。各交差を個別スライスにすると **指標数 M × エリア数 A** に膨張する（オーナー壁打ちで「掛け算で件数が膨れるのでは」と提起）。既存決定「全国化は対象コードの設定拡張」（確定索引・`docs/01`§4）を、掛け算を構造で避ける形へ具体化する。

現状のコードは既に足し算寄り：N03 投入は `cmd/ingest -pref`＝**都県パラメータ化済み**（runbook「9都県を順に流せる・pref_code 単位で DELETE→INSERT」）、`area_km2` は admin_unit から算出＝**エリア非依存**、FE 初期表示は `zoom 9`＝首都圏9都県が収まる、geometry/values/karte API に東京(13)絞り込みは無い。掛け算になるのは**タイル取得型指標（XKT013・地価XPT002・災害）の取得実行だけ**で、今 `fetch-xkt013.sh` が東京グリッド決め打ち（他県は範囲未定）。

## 結論（決定）

**データ拡張を2軸に分離し、足し算（M＋W）に保つ。**

- **指標＝コードのスライス（一度だけ・エリア非依存/パラメータ化）**。実装は1回。対象エリアはパラメータ（pref コード・タイルグリッド）で受ける。
- **エリア＝データ操作の「波（wave）」**。1つの波＝「対象エリアコードを段階リストに足し、“既に作った全指標”をその pref で再取得・再投入する」データ操作。波でコードは書かない（継ぎ目が済んでいれば）。
- **バックログは M（指標一覧）＋W（エリア波）の2軸で持つ**。交差（指標×エリア）はスライスにしない（＝ M×A の膨張を構造で防ぐ）。
- **エリア段階**（対応エリアコードを1箇所に段階付きで一元管理・追加＝リスト編集＋ingest再実行）：
  - 波1＝**1都3県**（東京`13`・埼玉`11`・千葉`12`・神奈川`14`）
  - 波2＝**北関東**（茨城`08`・栃木`09`・群馬`10`）
  - 波3＝**残り首都圏**（山梨`19`・静岡`22`）＝ MVP対応エリア（首都圏9都県）完成
  - 将来＝全国（対象コードの追加のみ）
- **継ぎ目**：
  - (a) N03／算出指標（`area_km2`）は既に pref パラメータ化済み＝波は `fetch-n03`＋`ingest -pref`＋指標再投入のデータ操作で済む。
  - (b) **タイル取得型指標（XKT013・地価・災害）は fetch/集計を「対象エリア（pref＋タイルグリッド）」パラメータ化する**（bbox→タイル範囲を自動算出）。tile-metric が多エリアになる**最初のとき**に一般化する（今の東京グリッド決め打ちを解消）。憶測で先に全県グリッドを作らない。
- **本ADRで着手＝波1（`area_km2`→1都3県）**＝N03/算出パスの波を実証（コード変更ほぼ無し・データ操作）。

## 検討した代替案と捨てた理由

- **各(指標,エリア)を個別スライス化** → 捨てた。M×A に膨張し、バックログとレビュー単位が破綻。
- **全エリアを最初から全指標で一括** → 捨てた。取得/検証コスト過大・段階で価値を出せない・トークン浪費（小エリアで作り検証→波で広げる方が軽い）。
- **エリアを指標コードに直書き** → 捨てた。拡張のたび改修＝掛け算の温床。パラメータ/設定化する。

## 影響（結果・トレードオフ）

- **得るもの**：バックログが足し算で膨張しない。段階（1都3県→北関東→残り首都圏）で価値を刻める。継ぎ目を一度作れば以後はデータ操作。
- **トレードオフ**：タイル指標は波ごとに取得実行が要る（実行/データ量は pref数×tile指標数で増えるが**コードでなく実行**・バッチ可）。トークン最小化＝**指標は小エリア（東京）で作り検証→安定後に波でまとめて広げる**（都度の再取得回数を減らす）。
- **正の更新**：`docs/99`（バックログを2軸＝指標一覧＋エリア波へ）・`docs/01`§4（段階を明記）。**対応エリアコードの一元設定**を導入（段階リスト）。
- **運用**：データは各環境で ingest 再実行が要る（DBローカル・`data/` は gitignore）＝デプロイ時の運用（`docs/runbooks`）。波の手順も runbook 化。
- **影響なし**：`ADR-0015`（空間結合の演算）・`ADR-0016`（配信）・指標の定義（`ADR-0006`〜`0011`）。本ADRは「拡張のかたち（軸の分離と段階）」だけを足す。
