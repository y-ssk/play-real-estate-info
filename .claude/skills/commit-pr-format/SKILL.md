# コミット / PR の様式（暫定）

> 参照チェーン：`CLAUDE.md` → `docs/commit-pr-format.md` → 本スキル。
> 様式の実体はここに隠蔽する。確定（ADR・学習メモを含む記録様式全体）は Step D（`docs/99_decision-register.md`）。

## 方針（`docs/04_harness.md` 第8節・`CLAUDE.md`）
- 「なぜ」を厚く残す（本丸＝ETL・データモデリング・地図表現）。周辺は薄く。
- コミットは意味のある最小単位。**コードと文書は同じ変更で更新**する。
- ADR が整備されたら「記録:」に ADR 番号を紐づける（現状は未付与可）。

## コミットメッセージ

```
<type>: <一言要約>

なぜ:
- <背景・目的>

内容:
- <何をしたか（箇条書き）>

記録: <関連ADR番号 / 同時更新した文書 / なし>
```

- `type` 例：`feat` / `fix` / `docs` / `refactor` / `test` / `chore`
- 1行目は要約のみ（72字目安）。本文との間に空行。

## PR 説明

> リモート未接続のため現状は様式のみ。リモート作成時に本節を
> `.github/PULL_REQUEST_TEMPLATE.md` へ転写すると GitHub で自動適用される。

```
## 概要
<このPRで何を達成するか（1〜3行）>

## なぜ
<背景・目的。本丸は厚く、周辺は薄く>

## 変更内容
- <主な変更>

## 記録
- 関連ADR: <番号 / なし>
- 同時更新した文書: <ファイル / なし>

## 確認（Feedback 4層・`docs/04_harness.md` 第5節）
- [ ] 層1 データの正しさ（ETL時。該当すれば）
- [ ] 層2 lint / 型 / test
- [ ] 層3 UI規約（UI変更時）
- [ ] 層4 目視確認（該当すれば）
```
